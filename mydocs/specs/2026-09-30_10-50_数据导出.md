## 1. Requirements (Context)

- **Goal**: 落地"透明，而且带得走"承诺的"带得走"半边：不用拷数据库文件，点两个按钮就能把数据全量下载。
- **In-Scope**:
  - `GET /api/export/data.json`：机器可读全量——账本**全部**记录（流水/计划/打卡/作废/休眠 goal 历史行，readAll 口径，含审计）+ 每个会话的完整事件流（cid/标题/伙伴/创建时间/九事件原文）
  - `GET /api/export/data.md`：人读时间线——生活记录按本地日分组（流水带分类/数值/备注，计划带周期/配额/截止日，打卡带状态），对话逐会话列出用户/助手文本轮次（工具调用/推理事件不进 MD）
  - 设置页新增「数据导出」区：两个按钮（JSON 全量备份 / Markdown 时间线），点击直接下载（复用记忆导出的 `<a href download>` 模式）
  - 导出文件名带日期（openprism-export-YYYYMMDD.json/.md）
- **Out-of-Scope**:
  - 不做导入/恢复（JSON 是全量快照，自跑用户可直接用 SQLite；结构化导入器另立 spec）
  - 不做任务/通知/记忆的导出（记忆已有 /api/memory/export；任务数据在 JSON 外，用户没点名——记 follow-up）
  - 不做按日期/分类过滤（全量即可，文件自己筛）
- **Acceptance Criteria**:
  - [ ] AC1: 登录态 GET /api/export/data.json → 200，Content-Disposition 附件下载；体含 exportedAt、账本全部记录（含已作废与休眠 goal 行）、每个会话的 events 数组；只有本人的数据
  - [ ] AC2: 登录态 GET /api/export/data.md → 200 text/markdown；按本地日分组的时间线（日期标题 + 计划建立/打卡/流水行），对话区每会话含标题与用户/助手文本轮次
  - [ ] AC3: 未登录访问两个路由 → 401（与其他 /api 同一道闸）
  - [ ] AC4: 设置页「数据导出」两个按钮，点击浏览器直接下载对应文件，无需右键另存
  - [ ] AC5: `pnpm test`、`pnpm typecheck`、web `tsc` 全绿；部署后线上验证一次真实下载

## 2. Research Findings

- **事实与约束**:
  - 账本读取现成：`Ledger.readAll()` 全量（含 void 与休眠 goal 行）；`activeRecords()` 为当前真相口径——MD 用 active（人读当前事实），JSON 用 readAll（机器可审计全量）。
  - 会话读取现成：`ConversationStore.list(uid)` 给会话清单（cid/title/agentId/pinned/createdTs），`readEvents(cid)` 给九事件完整原文；归属在 conversations 表（uid 匹配才导）。
  - 下载模式现成：/api/memory/export 直接 `writeHead(200, {Content-Disposition: attachment})`；web 端 `<a href={url} download>` 即可触发，Cookie 鉴权天然随请求带上。
  - 事件类型：消息事件 type 为 `user/message` / `assistant/message`，消息体在 `event.message.content`（文本块 type=text 取 .text）；MD 只取这两类。
  - 日期分组时区：users 表有 tz_offset_minutes（浏览器上报）；MD 按它分本地日，缺省按 UTC 0（用户档案已设 480）。
  - server.ts 已 1300+ 行——MD/JSON 组装放独立纯函数文件 `src/app/export.ts`，路由只做 IO，可单测。
- **现状链路**: 无任何账本/对话导出接口（仅记忆）。
- **风险与不确定项**:
  - 体积：对话事件多时 JSON 可到数 MB——一次性下载可接受，不做流式压缩（记 follow-up：将来可加 gzip）。
  - `readEvents` 默认有 limit 上限吗？——核实点：conversations.ts:198 options.limit 缺省行为（Execute 第一步确认，导出需全量路径）。
  - MD 对话若含图片等块——只渲染文本块，其余块标 `[图片]`/`[附件]` 占位。

## 3. Innovate (Optional: Options & Decision)

### Option A（双格式双路由：JSON 全量 + MD 时间线）
- Pros: 机器可读（可再处理/未来导入器）与人读（直接翻看）两个需求一次满足；MD 按 active 口径不被作废记录干扰
- Cons: 两个产物要维护
### Option B（只做 JSON）
- Pros: 最少代码
- Cons: 用户打开是一坨机器格式，"带走"了但"看不了"；非技术用户等于没有
### Decision
- **Selected: Option A**
- **Why**: 用户原话"可以……导出的功能"指向可拿走可用；双格式成本可控（纯函数组装）
