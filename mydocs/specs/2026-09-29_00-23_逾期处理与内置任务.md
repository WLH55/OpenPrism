> **Goal**: 逾期计划给"跳过"入口（作废留痕）；每用户内置三个定时任务（每日简报 08:30 / 每日晚间汇报 20:00 / 每周复盘周日 21:00），默认站内渠道、可改可关可删且删除不复活；今天页计划区加范围切换（今天/本周/全部/已完成）
> **Scope**: 今天页逾期跳过 + 范围切换四视图 + TaskStore 内置种子（启动/注册两条种入路径 + users 表种子标记防复活）+ 提醒页内置徽标与模板对齐

## 1. Requirements (Context)
- **Goal**: 见状态块。两个子需求来自用户验收对话：① 逾期项要能"补做或跳过"（补做=点圈打卡已存在，跳过缺入口）；② 简报/复盘做成内置任务而非纯靠用户自建模板，且每周复盘从周一 20:00 挪到周末晚、新增每天 20:00 晚间汇报。
- **In-Scope**:
  - 今天页逾期（state=overdue）计划行加「跳过」按钮：确认后作废该 plan 记录（走 /api/void，留痕可审计），列表刷新消失
  - TaskDef 增 `builtin?: "daily-brief" | "daily-report" | "weekly-review"`；tasks 表加 builtin 列（ALTER TABLE 幂等迁移）
  - TaskStore.ensureBuiltins(uid)：种三个任务——每日简报（daily 08:30，指令沿用现有模板文案）、每日晚间汇报（daily 20:00，查 what=today 汇报完成度、邀请补卡/跳过/记一笔）、每周复盘（weekly 周日 21:00，原周一 20:00 挪来，偏周回顾+下周聚焦）；tz 默认 480（东八区），notifyChannel 默认 inapp
  - 种入路径两条：注册成功后 + 进程启动对存量用户补种（仿 runConsolidateForAll("startup")）
  - 防复活：users 表加 `builtins_seeded` 标记列，种子一次性；用户删除内置任务后重启不得重建
  - 今天页计划区加范围切换（分段控件，样式照盘面页周期切换）：**今天**（默认：逾期 + 今天截止 + 进行中/待做习惯 + 今日已完成，未来项移出默认视图）/ **本周**（+截止日 ≤ 本周日的未来项）/ **全部**（所有进行中含远期）/ **已完成**（近 30 天完成存档，含已沉出的）；折叠层补 `doneAt`（完成时刻），已完成不再从数据沉出、改由前端按视图过滤
  - 提醒页：内置任务显示「内置」徽标；模板按钮三枚对齐（简报 08:30 / 晚间汇报 20:00 / 每周复盘周日 21:00——原"每周报告周一 20:00"按钮更新）
- **Out-of-Scope**:
  - 内置任务的"恢复默认"入口（删了可用模板按钮一键重建，不做专门恢复机制）
  - update_plan 工具（挪挂靠/改日期，遗留缺口另排）
  - 微信渠道自动切换（默认站内，用户手动改）
- **Acceptance Criteria**:
  - [ ] AC1 逾期行有「跳过」，confirm 后计划作废（账本留 void 记录）并从今天页消失；非逾期行无此按钮
  - [ ] AC2 任意用户启动后拥有三个内置任务，触发时刻分别为 08:30 / 20:00 / 周日 21:00（tz=480）
  - [ ] AC3 种子幂等且一次性：重复启动不重复建；删除内置任务后重启不复活（AC 依据 users.builtins_seeded）
  - [ ] AC4 注册新用户自动获得三件套（注册路径种入）
  - [ ] AC5 提醒页内置任务带「内置」徽标；三枚模板按钮时间与新口径一致
  - [ ] AC6 pnpm test / typecheck / build:web 全绿，新增用例覆盖跳过折叠字段与种子幂等
  - [ ] AC7 范围切换四视图：默认「今天」不含未来项；「本周」含截止 ≤ 本周日的未来项；「全部」含远期；「已完成」显示近 30 天完成（含 due 已过的沉出项，按完成时间倒序）
  - [ ] AC8 已完成项带 doneAt（服务端折叠），切换视图不额外请求（一次载荷前端过滤）

## 2. Research Findings
- **事实与约束**:
  - `TaskDef`（tasks.ts:19）：id/uid/agentId?/title/instruction/trigger/enabled/notifyChannel?/tzOffsetMinutes/createdTs/lastRunTs；`create(uid, input)` 校验 title/instruction/trigger/notifyChannel
  - tasks 表 DDL（db.ts:136）列式存储 + trigger_json；加 builtin 需 `ALTER TABLE tasks ADD COLUMN builtin TEXT`（PRAGMA table_info 嗅探幂等，仓库已有 ensureGoalKind 事务化先例）
  - 周触发为 ISO 周序（Tasks.tsx 周一=setWeekdays([1])）→ 周日=7
  - 取消计划的语义（tools.ts cancel_plan）= 追加 void(targetSeq=plan.seq)；/api/void 已拒收 goal、放行 plan——UI 跳过可直接复用，但 TodayPlanView 目前**没有 seq**，需折叠层补
  - todayView 已有确定性 state（overdue 排最前）；跳过按钮只挂 state==="overdue" 行
  - 种入锚点：server.ts:250 /api/auth/register（建号成功后）；main.ts listen 后（runConsolidateForAll("startup") 同款位置），`users` Map 可枚举全部 uid
  - 防复活不能只靠"查 builtin 是否存在"（删除后查不到会重建）→ users 表加 `builtins_seeded INTEGER` 标记列，种子一次性
  - 晚间汇报/周复盘的指令要利用已有能力：agent 到点可 query_ledger what=today（含 plans 状态、top3、goalCard）
- **现状链路**: 调度器（Scheduler）按 trigger 到点 → taskRunner 注入触发上下文跑回合 → 站内通知兜底 + 可选微信加推；模板按钮（Tasks.tsx）只预填表单不落任务
- **风险与不确定项**:
  - R1 内置指令文案的"温度"（考官 vs 朋友）首次上线需真机调——验收靠用户体感，文案放 TaskStore 常量便于热改
  - R2 tz 默认 480 硬编码：单用户自部署可接受；多时区用户需手改（Out-of-Scope）
  - R3 ALTER TABLE 两张（tasks.builtin、users.builtins_seeded）——沿用事务化嗅探模式，风险低
