## §1 Requirements

- 创建伙伴时，名字只认表单显式输入；persona_md 里写 `# 什么` 不再影响名字（2026-09-07 起 H1 本就只作创建兜底，本次连兜底也删）。
- 全系统不再有任何代码读取 persona 的 markdown 结构——`extractAgentName` 删除，杜绝复活。
- 前端引导一致：向导/编辑页 placeholder、五个 SOUL_TEMPLATES 均不再暗示"md 开头要写名字"；向导灵魂留空时合成占位文案不再拼 `# 名字` 头。
- API 兼容：`POST /api/agents` 的 `name` 仍可选（直连脚本缺省「助手」），向导必显式给名（第①步 canContinue 校验既有）。

## §2 Research Findings

- **引用面干净**：extractAgentName 全仓库仅 agents.ts create 兜底一处生产调用 + 一处单测。
- **兜底链现状**：`create` 里 `input.name?.trim() || extractAgentName(persona) || "助手"`；向导提交时 `persona 为空则合成 "# 名字\n（向导创建…）"`——两处都在制造"名字藏在 md 里"的假象。
- **连带依赖**：app-conversations 的 ensureTaskFeed 用例与 app-server 的 HTTP 创建用例均靠 H1 拿到「教练」，需改为显式传名（恰好也是新语义的正确示范）。
- **测试夹具坑**：app-agents 的 `store()` randomUUID 固定 "aid-1"，同库二次 create 撞主键（id 全局 PK）；改自增序列，snapshotSync 用例改用返回的 entry.id。
- **文档债**：soulTemplates.ts 头注释声称"与 src/app/soul-templates.ts 保持同款"，该文件并不存在——顺手修正。

## §5 与既有设计的差异说明

- 2026-09-03 batch2 spec（"名字从 H1 推导"）与 2026-09-07 向导 spec（"H1 推导保留为兜底"）为历史记录，不回改；本 spec 为现行口径——理由：名字是结构化资产（列表展示/会话归属/feed 命名都消费它），混在自由文本里推导只会制造"改 md 头能不能改名"的歧义；表单字段 + 显式 updateIdentity 才是单一事实源。
