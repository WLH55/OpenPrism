## 1. Requirements (Context)

- **Goal**:
  1. **微信对话**：在微信里给 bot 发消息 → 进入 OpenPrism 会话跑回合 → 回复推回微信；不打开 web 也能日常对话。

- **In-Scope**:
  - iLink API 的 TS 移植（扫码登录 / getupdates 长轮询 / sendmessage / token 过期处理）。
  - 微信消息 ↔ OpenPrism 用户/会话的路由与绑定校验。
  - 「IM 通道」页（新 view）：微信机器人扫码绑定/解绑/过期态；「通知通道」页撤下微信占位卡。
  - 任务级通知渠道：`tasks.notify_channel`（inapp 默认 / wechat）+ 表单选择 + taskRunner 按渠道推送。
  - 测试：注入 fake iLink（零网络铁律）。
- **Out-of-Scope**:
  - harness / 会话日志模型改动（微信消息走既有 `conversations.send()`，日志照常重建）。
  - 微信侧多会话切换命令、群聊、图片/语音/文件消息（首版纯文本；iLink 类型已摸清，留作后续）。

## 2. Research Findings

- **WeKnora 的微信接入 = 腾讯 iLink Bot API**（`ilinkai.weixin.qq.com`，Go 实现 ≈ 900 行，TS 移植量可控）：
  - **协议形态**：无 WebSocket、无 Webhook，纯 HTTP——**出站长轮询**收消息 + REST 发消息。对自部署极友好：不需要公网入站/回调 URL（与 OpenPrism 当前公网部署同模型）。
  - **扫码登录**：`GET /ilink/bot/get_bot_qrcode?bot_type=3` → `{qrcode, qrcode_img_content}`（图片 URL，前端 `<img>` 直接展示）→ `GET /ilink/bot/get_qrcode_status?qrcode=xxx`（长轮询 ~35s，状态 wait/scaned/confirmed/expired）→ confirmed 后得 `bot_token` + `ilink_bot_id` + `ilink_user_id`。
  - **收消息**：`POST /ilink/bot/getupdates`（Bearer bot_token + `AuthorizationType: ilink_bot_token` + 随机 `X-WECHAT-UIN` 头；body 带 `get_updates_buf` 游标）→ `msgs[]`：message_type 1=用户 2=bot，item_list 类型 1=文本 2=图片 3=语音(自带转写文本) 4=文件；每条带 `context_token`（回复时回传）。
  - **发消息**：`POST /ilink/bot/sendmessage`（to_user_id + context_token + item_list 文本，message_state=2 FINISH）；另有 `/ilink/bot/sendtyping`。
  - **Token 过期**：errcode -14 → 需重新扫码。退避重连 1s→30s 指数、无限重试（`longpoll.go`）。
  - **媒体**：CDN `novac2c.cdn.weixin.qq.com` + AES-128-ECB 解密（Node `crypto` 原生支持）——首版不接。
- **WeKnora IM 服务层架构**（供借鉴，不必照搬）：Adapter 接口统一九平台；会话按 (platform, user_id, chat_id) 解析；QA 队列限并发；流式 = streamSection 缓冲分段整条 SendReply（非消息编辑）。
- **本仓库现状**：
  - `notify.ts` 已预留 `NotifyChannel` 通道缝（注释明言「微信桥等后续接入，D9.2 双向网关架构位」），`NotificationStore.push` 为单一落点，加通道 = 在 main.ts 装配处加数组元素。
  - `NotifyChannels.tsx` 为占位页（微信卡「待接入」+ 禁用按钮），本次调研直接回答其页脚遗留的选型问题。
  - 会话侧：`conversations.send()` 已是异步入口（followup 后 202），`ensureTaskFeed` 已有「固定会话」先例可复用为微信固定会话。
  - 凭据加密：`secretbox.ts` 的 seal/open（主密钥 AES）可直接存 bot_token。
  - 零网络铁律：iLink 客户端必须经 `PlatformEnv.fetch` 注入（铁律 1/5 的 app 层对应物）。
- **风险与不确定项**:
  - iLink 是腾讯内部开放接口，无公开文档；WeKnora（腾讯官方开源）在生产使用，通道可用性有背书，但限流策略/token 有效期需实测（-14 过期后重扫即可恢复）。
  - iLink 社交模型细节（bot 与扫码者的对话形态、from_user_id 是否恒等于 ilink_user_id）需绑定后实测确认——不影响架构（收消息按 from_user_id 白名单校验即可）。
  - 微信消息进会话后，web 端同步可见（同一日志），无额外一致性工作。

### Option A：iLink Bot API 直连（TS 移植 WeKnora 的 wechat/ 包）

### 4.5 增补 Plan（2026-09-28 15:05，用户提出：微信机器人绑定的伙伴可见、可切换）

现状：「微信对话」会话（`wechat:<uid>`）未绑伙伴 = 默认助手；conversations.switchAgent 基建现成但不支持切回默认（agent_id 置 NULL 语义缺失，web 聊天页同样 no-op）。微信场景会话唯一固定、不能靠新建会话绕过，必须支持来回切。

- `src/app/conversations.ts`：`switchAgent(uid, cid, agentId: string | null)`——null = 切回默认助手（agent_id 置 NULL，switches 记 `agentId: null`）；多模态前置检查目标为 null 时按全局激活模型判。
- `src/app/wechat-bridge.ts`：`currentAgent(uid): Promise<string | null>`（读 wechat feed 会话绑定，无会话 = null）；`switchAgent(uid, agentId)`（复用私有 ensureFeed 确保会话存在后透传 conversations.switchAgent）。
- `src/app/server.ts`：`GET /api/wechat/bind/agent` → `{ agentId: string | null }`；`PUT /api/wechat/bind/agent`（body `{ agentId: string | null }`）；`PUT /api/conversations/:cid/agent` 的 body.agentId null 透传（不再 `String(?? "")` 吞 null）。
- `web/src/api.ts` + `web/src/pages/IM.tsx`：绑定卡下加「对话伙伴」行——下拉（默认助手 + 伙伴列表）显示当前值，onChange 切换；提示语说明 web/微信同一会话同步生效。
