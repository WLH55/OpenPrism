## 1. Requirements (Context)

- **Goal**: 修复 2026-09-29 对话中评估出的账本工具缺口，使模型具备：改计划、补/撤打卡、按 goalId 过滤计划、限量查询、人话回执、准确的参数描述。
- **In-Scope**:
  1. 新增 `update_plan` 工具：部分更新 title/scope/due/ndays/goalId，planId 不变，历史可审计。
  2. `checkin_plan` 增可选 `date`（YYYY-MM-DD）与 `time`（HH:mm）参数，支持补历史卡；拒绝未来日期。
  3. `void_flow` 放开对 checkin 记录的作废（撤卡）；plan 记录引导走 cancel_plan；goal 记录拒绝。
  4. `query_ledger` what=plans 增 `goalId` 过滤；plans/flows 增 `limit`（默认 200），截断时返回 `total` 与 `truncated: true`。
  5. `query_ledger` render 按 what 输出人话摘要（替换裸 JSON.stringify）。
  6. `update_goal` 描述修补：parentId 补「空串=解除父级」；nextStep 标弃用（与 create_goal 同规）。
- **Out-of-Scope**:
  - 时区口径统一（tools 层写死 UTC vs UI 传 tz）：agent 会话无 tz 来源，需产品决策（见 Q1）。
  - goal 真删工具：UI 已有 DELETE /api/goals/:goalId，agent 侧 archived 够用。
  - UI 侧对应能力（改计划路由、UI 补卡入口）：本 spec 只做工具层（见 Q2 Follow-up）。
  - query_ledger what=goals/today 的结构变化。
- **Acceptance Criteria**:
  - [ ] AC1 update_plan：改标题/due/goalId 后 `query_ledger what=plans` 反映新值且 planId 不变；readAll 中旧 plan 记录已被 void 引用（历史审计保留）；goalId 传空串后 plans 列表该项无 goalId。
  - [ ] AC2 补卡：checkin_plan 传 date=昨天 → 账本 checkin 记录 at 落在昨天；date=未来日期 → execute 抛错；不传 date/time 行为与现状一致（at=now）。
  - [ ] AC3 撤卡：打卡后 void_flow(该 checkin 的 seq) → todayView 中该计划回到未完成（deadline 型 doneEver 消失）；void_flow 指向 plan seq → 报错提示用 cancel_plan；指向 goal seq → 报错拒绝。
  - [ ] AC4 过滤限量：what=plans & goalId=g1 只返回挂 g1 的计划；limit=1 且共 3 条时返回 1 条 + total=3 + truncated=true；不传 limit 返回全部（≤200 时无 truncated）。
  - [ ] AC5 render：query_ledger 四种 what 的 render 均为一句人话摘要，非 JSON 串。
  - [ ] AC6 update_goal parentId 描述含空串语义、nextStep 描述含弃用标注；`pnpm test` 与 `pnpm typecheck` 全绿。

## 2. Research Findings

- 事实与约束:
  - `PlanRecord` 无快照机制：一 planId 一条记录（`src/app/ledger.ts:34`）；goal 才有「同 goalId 最新快照胜出」语义（`src/app/goals.ts:9`）。
  - UI 的 `/api/void`（`src/app/server.ts:982`）是通用作废口：接受 event/plan/checkin，仅拒 goal；「撤销打卡 = void 该 checkin 的 seq」是既有先例（server.ts:1019 注释与 doneSeqs 实现）。
  - UI 也不能改计划：server.ts 仅有 `POST /api/plans`（server.ts:1038），无 PUT/PATCH；UI 打卡 at 固定 now（server.ts:1006）——补卡与改计划是双侧缺口，本 spec 先补工具侧。
  - `void_flow` 现只认 kind=event（`src/app/tools.ts:255`）；「逾期跳过 = void plan 记录 seq」已是 UI 侧对 plan 用 void 的先例（fold.ts TodayPlanView.seq 注释）。
  - `query_ledger` what=plans 无过滤无 limit（tools.ts:209-218）；flows 有 category/from/to 但无 limit；render 是 `JSON.stringify`（tools.ts:199），其余七工具均有人话 render。
  - 工具层 today/goals 视图 tzOffsetMinutes 固定 0（UTC 口径，tools.ts:204-207 注释自认），UI 从 query 传 tz（server.ts:958/1014）。
  - `update_goal` merged 时 `...cur` 展开携带旧 seq/ts/source/actor，但 append 会重分配并显式覆盖（tools.ts:426-427），行为正确。
  - 测试基建：`test/app-tools.test.ts` 用 `testDb()` + 固定 `NOW = Date.UTC(2026, 8, 3, 12, 0, 0)`（UTC+8 当天 20:00），工具经 `createLedgerTools` 装配，直接断言 execute 返回值与 ledger 记录。
- 现状链路: 工具装配在 conversations.ts:450-479（ledgerTools 受 binding.tools 白名单过滤——新增工具默认全给，无需改装配层）。
- 风险与不确定项:
  - update_plan 若走 plan 快照语义需改 fold 层全部 plan 消费点（todayView/goalView/top3/server milestones），回归面大——已决策走「追加新版本 + void 旧记录」（见 §3）。
  - 「追加新 + void 旧」是两次 append，非原子：单进程串行写队列下仅毫秒级理论窗口可能出现同 planId 双活跃记录，接受（与 UI 既有「跳过」机制同构）。
  - plans/flows 返回结构加 total/truncated 字段，可能破坏现有严格相等断言——需同步更新既有用例。
  - render 文本变化可能影响断言 render 的既有用例（grep 后未见，执行时复核）。

## 3. Innovate (Optional: Options & Decision)

### Option A
- 方案: update_plan 走 plan 快照语义（同 planId 最新记录胜出，学 goal 的 latestGoalSnapshots）。
- Pros: 与 goal 修订机制对称；不产生 void 记录。
- Cons: fold 层所有 plan 消费点（todayView/goalView/top3/tools/server milestones）都要换「最新版本」语义，改动面大、回归风险高。
### Option B
- 方案: update_plan = 追加新 plan 记录（同 planId、合并后字段）+ append void 指向旧记录 seq。
- Pros: 与「逾期跳过」（void plan seq）机制同构；fold/activeRecords 零改动；planId 稳定故历史打卡引用不断；审计层历史全保留。
- Cons: 两次 append 非原子（毫秒级理论窗口）；账本多一条 void 记录。
### Decision
- Selected: Option B（撤卡同理：扩展 void_flow 而非新增 uncheckin_plan 工具，与 UI 通用作废口对齐，控制工具数量）。
- Why: 最小改动面 + 与既有机制同构 + 审计完整；快照语义的对称性收益不抵 fold 层回归风险。

### 4.2 Signatures

- `function parseAt(date: string | undefined, time: string | undefined, now: number): number` — date 缺省=注入今天；time 缺省=当前时分；date 晚于注入今天 → throw（未来不可预打卡）。
- `update_plan` 参数 schema: `{ planId: string(必填), title?: string, scope?: "day"|"week"|"month"|"year"|"ndays"|"deadline", due?: string, ndays?: integer, goalId?: string(空串=解除挂载) }`；execute 返回 `{ planId, title, ...(goalTitle) }`。
- `checkin_plan` 参数追加: `date?: string(YYYY-MM-DD), time?: string(HH:mm)`；返回不变。
- `void_flow` 参数不变（seq + reason）；目标类型校验放宽为 event | checkin。
- `query_ledger` 参数追加: `goalId?: string(what=plans 时过滤), limit?: integer(默认 200，plans/flows 生效)`；plans/flows 返回体追加 `total: number, truncated: boolean`。
