## 1. Requirements (Context)
- **Goal**: 上下文压缩的摘要指令与产品定位一致——个人助理会话被压缩时，摘要保留的是用户近况、目标计划、约定承诺、关键事实，去除 coding 视角小节
- **In-Scope**:
  - `CompactionConfig` 增加 `summaryInstruction` 配置，摘要请求改用配置值
  - app 层（会话装配处）注入个人助理口径指令（web / 微信桥 / 任务触发三入口同一装配，同源生效）
  - harness 缺省指令改为领域中立口径（库不带 coding 偏见）
- **Out-of-Scope**:
  - 压缩触发阈值、遮蔽区间选择、shrink 校验等算法行为（不变）
  - `compaction/summary` 事件结构与投影（不变，invariants 零改动）
  - 手动压缩入口（另立）
- **Acceptance Criteria**:
  - [ ] AC1 会话压缩触发时，发给模型的摘要指令为个人助理口径（含「用户近况与情绪 / 目标与计划 / 约定与承诺 / 关键事实 / 未完成与待跟进 / 关键上下文」小节）
  - [ ] AC2 未配置 `summaryInstruction` 时缺省为中立口径，不含「文件与代码」「错误与修复」字样
  - [ ] AC3 逐字保留要求改为个人助理要素：日期与时间点、数值（组数、次数、配额、体重等）、人名与称呼、用户原话承诺
  - [ ] AC4 `pnpm test` + `pnpm typecheck` 全绿（既有用例零引用旧指令文本，已核实无碎裂面）

## 2. Research Findings
- **事实与约束**:
  - 摘要指令写死在 harness 通用层：`src/harness/context/compact.ts:54-65` `SUMMARY_INSTRUCTION`（八小节：任务意图/关键概念/文件与代码/错误与修复/未竟事项/当前工作/下一步/关键上下文，逐字保留要求为文件路径、命令、错误原文、数值）。
  - 使用点唯一：`requestSummary`（`compact.ts:111-131`）把指令作为末条 user 消息追加；摘要请求复用会话前缀（同 system + tools + 被压区间消息）保 KV cache 命中。
  - 配置覆盖链现成：`AgentConfig.compaction?: Partial<CompactionConfig>`（`src/harness/core/agent.ts:41`）→ 合并 `DEFAULT_COMPACTION`（`agent.ts:86-90`）→ `compactDeps.config`（`agent.ts:145`）→ `compactConversation`。app 装配点 `src/app/conversations.ts:607-631`（`createAgent` 处，已有 `model.contextWindow` 同类覆盖先例 `conversations.ts:613-616`）。
  - 测试引用面：`grep 任务意图|关键概念|未竟事项|SUMMARY_INSTRUCTION|summaryInstruction` 全仓仅命中 `compact.ts` 自身——mock adapter 返回固定摘要文本，不 parse 指令；改指令内容与加配置字段均不碰既有断言。
  - 会话三入口（web `send()` / 微信桥 / 任务触发）共用同一 `agent()` 装配函数（`conversations.ts:607`），指令在装配处注入即三入口同源。
- **现状链路**: 压缩触发 → `requestSummary` 用写死的 coding 口径指令 → 模型按八小节产出摘要 → `compaction/summary` 事件 + checkpoint 替换遮蔽区间。
- **风险与不确定项**:
  - 指令文案变化影响摘要质量属模型行为固有不确定性，验收以指令内容本身为准（AC1-AC3），摘要实际质量靠真机观察。
  - 历史已生成的摘要 checkpoint 不受影响（它们是既成文本）。

## 3. Innovate (Optional: Options & Decision)
### Option A 指令可配置 + app 注入 + harness 缺省中立化
- 内容: `CompactionConfig.summaryInstruction`（必填字段，`DEFAULT_COMPACTION` 给中立缺省）；app 装配处传个人助理口径常量
- Pros: app 语义归 app 层（harness 保持通用库定位，与 AGENTS.md 架构一致）；三入口装配处一处注入；未来其他部署形态可换指令
- Cons: 多一个配置字段与一条装配传参
### Option B 仅重写 harness 缺省为个人助理口径
- 内容: 直接把 `SUMMARY_INSTRUCTION` 改成个人助理八节→六节文案，不加配置面
- Pros: 改动面最小
- Cons: 陪伴/课表语义写进通用 harness 库，库与单一应用耦合，与仓库「harness 通用机制 + app 语义分层」的既有架构口径相悖
### Decision
- Selected: Option A
- Why: 架构口径正确（app 语义归 app），且配置面成本极低（一个必填字段 + 一处传参）
### Skip (for small/simple tasks)
- Skipped: false
- Reason: 存在两个成立方案，涉及架构分层口径，需明示决策
