## 1. Requirements (Context)

- **Goal**: 两个特性一次交付：
  - **A 周期计划习惯化**：用户说"每周运动三天"，系统要能追踪"本周第几天了、完成几次了"，打满 3 次才显示全部已完成，跨周自动清零重开；day/week/month/year 四种周期锚定"创建周期"的问题一并解决（习惯计划不再过期淡出）。
  - **B 任务编辑入口**：提醒页任意任务（含内置三件套）可编辑标题/指令/调度/通知渠道；内置任务改过指令后，启动时的指令单源同步不再覆盖用户修改，并可一键恢复默认文案。
- **In-Scope**:
  - PlanRecord 加 `timesPerPeriod?: number`（存在即习惯计划：跨周期续期 + 每周期配额）
  - 折叠层（todayView/top3/stateOf）：习惯计划的周期归属、进度计数、完成判定、撤销凭据
  - 工具层（create_plan/update_plan 参数与教学文案、query_ledger today 回执进度行）
  - HTTP 层（POST/PUT /api/plans 收 timesPerPeriod）
  - 今天页 UI（进度芯片 n/N、打卡交互、Top3 进度）
  - tasks 表加 `customized` 列；TaskStore.update 白名单 + resetInstruction；ensureBuiltins 跳过已自定义
  - 提醒页任务行「编辑」入口（复用调度选择器）、内置任务「恢复默认文案」
  - persona/CONTEXT.md/设计文档口径同步
- **Out-of-Scope**:
  - 不做习惯计划的**历史周期完成度回溯视图**（如"过去 8 周每周达标几次"图表）——打卡数据都在账本里，留 follow-up
  - 不做 UI 上创建/修改计划表单（建计划仍走对话；UI 编辑仍只有标题/due）
  - 不做任务 agentId/tzOffsetMinutes 的编辑（update 不支持，留 follow-up）
  - 不动 ndays/deadline 语义（一次性冲刺/截止日本来就是锚定设计）
  - 不做计划"重复提醒/推送"（那是定时任务的事）
- **Acceptance Criteria**:
  - [ ] AC1: week+timesPerPeriod=3 的计划，第 1 个打卡日显示"本周 1/3·进行中"；3 个不同本地日后 state=done（划线"已完成"）；下周一视图自动变"本周 0/3·待做"（打卡归新周期，旧卡不算数）
  - [ ] AC2: 无 timesPerPeriod 的存量计划行为与现在完全一致（覆盖判定/过期淡出/state 机），零迁移零回归
  - [ ] AC3: scope=deadline/ndays 传 timesPerPeriod（工具层与 HTTP 层）报明确错误；timesPerPeriod 非正整数报错
  - [ ] AC4: day+timesPerPeriod=N 按**打卡次数**计（同日多卡各算一次）；week/month/year 按**不同本地日数**计（同日多卡只算 1 天）
  - [ ] AC5: 提醒页任意任务点「编辑」可改标题/指令/调度/通知渠道，保存后立即生效（列表与下次触发都按新值）
  - [ ] AC6: 内置任务改指令后 `ensureBuiltins` 不再覆盖该任务；「恢复默认文案」还原 DEFS 副本并恢复同步；非内置任务调 resetInstruction 报 400
  - [ ] AC7: 模型可见面同步：create_plan 教学含新口径；today 回执对习惯计划显示"本周 2/3"式进度；persona 口径更新
  - [ ] AC8: `pnpm test`、`pnpm typecheck`、web `tsc` 全绿；存量 DB 迁移幂等（ensureColumn 路径）

## 2. Research Findings

- **事实与约束**:
  - `planScopeCoversToday`（fold.ts:79）：day/week/month/year 全部锚定 `plan.ts`（创建时刻）所在周期——习惯"下周就消失"；ndays 锚创建是故意（一次性冲刺）；deadline 锚 due。`periodHasCheckin` 用 `planScopeCoversToday(plan, r.at)` 判断打卡是否落在计划周期内，整体自洽。
  - `PlanRecord`（ledger.ts:34）无任何次数字段；工具教学（tools.ts:87）却写"周期习惯用 day/week/month/year/ndays（每个周期重新打卡）"——文案与折叠行为不一致，模型会自信地建出次日即失效的"每天背单词"。
  - UI 计划行（Today.tsx PlanRow）：周期型 `state=done`（今天打过一次卡）即划线"已完成"，同日第二击是撤销不是再打卡；点击语义 = toggle。
  - TaskStore.update（tasks.ts:497）已支持 enabled/instruction/title/trigger/notifyChannel，PUT /api/tasks/:id（server.ts:1105）全透传，内置任务无限制——**编辑缺的只是 UI**。
  - ensureBuiltins（tasks.ts）每次登录/启动把内置任务 instruction 同步回 BUILTIN_TASK_DEFS（种子楔子修复）——若直接放开 UI 编辑，用户改的文案下次重启即被覆盖。必须配"已自定义"标记。
  - db.ts:366 `ensureColumn` 是存量库加列的既有通道；tasks 表建表在 db.ts:138；ledger_entries 建表含 plan 专列（plan_id/title/scope/due/ndays/plan_goal_id）。
  - 服务器存量数据（2026-09-30 勘察）：ledger 67 条、12 条休眠 goal 行；习惯化用"字段存在性"门控，存量 week/month/year 计划（无字段）保持旧锚点语义，无需迁移。
  - web `api.updateTask`（api.ts:426）已声明 instruction/title/notifyChannel/trigger patch 类型；TaskLoose 无 customized。
- **现状链路**:
  - 计划：UI/对话 → create_plan 工具或 POST /api/plans（内联校验）→ ledger.append(plan) → todayView 折叠 → 今天页/TOP3/renderQuery。
  - 修订：update_plan / PUT /api/plans → mergePlanUpdate（plans.ts，纯函数）→ 追加新版本 + void 旧行。
  - 任务：Tasks.tsx taskRow 只有 历史/立即跑/删除/Toggle；PUT 已通；指令同步在 ensureBuiltins。
- **风险与不确定项**:
  - 折叠层 `done`/`doneToday`/`doneSeqs` 语义在习惯计划下要重定义（done=本期配额达成），todayView 内多处（stateOf、doneSeqs 分支、30 天窗口、top3）耦合同一套语义，改动需整体过一遍；test/app-fold-plan.test.ts 是回归锚。
  - 近 30 天完成存档按"当前 state=done"取——习惯计划跨期重置后，往期达标不再出现在存档行（打卡明细仍在账本/回执 checkins 里）。已知局限，记 follow-up，不在本 spec 解决。
  - Tasks.tsx 700 行单文件，调度选择器（schedKind 簇 ~20 个 state）要抽组件给创建/编辑共用，注意别顺手重构无关部分。
  - 同日多卡：week 口径下 UI 第二击不该再记账（按天计数，记了也不涨）——需明确交互文案；day 配额则允许多次。

## 3. Innovate (Optional: Options & Decision)

### Option A（单字段 timesPerPeriod，字段存在性 = 习惯语义）
- Pros: 一个字段同时表达"跨周期续期"与"每期配额"；缺省路径零改动（存量数据天然走旧语义）；无 repeat∧无配额的中间态要定义
- Cons: "续期"与"配额"两个概念耦合在一个字段上，教学文案要讲清
### Option B（repeat: boolean + timesPerPeriod 两个字段）
- Pros: 概念正交，repeat 单独表达"无配额习惯"
- Cons: 中间态（repeat 无配额）仍需定义完成口径（等价配额 1）；两个字段的组合校验面更大；教学更绕
### Option C（改 planScopeCoversToday 锚点为"当前周期对齐"，全员习惯化）
- Pros: 不加字段，教学文案"每个周期重新打卡"即刻成真
- Cons: 存量"本周读完 X"式一次性周计划会永久复活成永不过期待办，需要数据迁移猜意图——不可接受
### Decision
- **Selected: Option A**（timesPerPeriod 单字段，day 按次 / week·month·year 按不同本地日计数，配额达成即本期 done，跨期自动清零）
- **Why**: 零迁移、零存量回归、无中间态；与用户"打满三次才算完成、判断本周第几天"的表述直接对应；Option C 的存量复活问题否决
### Skip (for small/simple tasks)
- Skipped: false
- Reason: 模型级特性，三方案实质差异已裁定
