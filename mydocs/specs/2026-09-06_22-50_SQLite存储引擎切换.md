## 0. Open Questions
- [x] None（用户已裁决全部关键分歧，见 §3 Decision）

## 1. Requirements (Context)
- **Goal**: 将 OpenPrism 的存储引擎从 append-only JSONL 文件整体切换为 SQLite 领域表建模（强类型列、索引、SQL 查询），并取消"启动全量载入内存"的读模型。
- **In-Scope**:
  - 13 张领域表建模（users/sessions/ledger_entries/conversations/conversation_events/agents/skills/mcps/tasks/task_runs/notifications/memory_slots+memory_meta/model_config/archives/meta）
  - 全部存储模块内部 SQL 化；harness 会话日志抽 `SessionEventStore` 注入缝
  - 一次性迁移器（旧 JSONL/markdown → DB，幂等，旧文件不删）
  - 测试改造（app 级 12 个测试换 `:memory:` SQLite 夹具；新增对拍测试）
  - ADR 0008 + README 更新
- **Out-of-Scope**:
  - 面板折叠层 fold.ts 的纯函数逻辑（输入契约不变）
  - server.ts 路由层业务语义（仅改数据来源）
  - web/ 前端（仅经 /api 通信，零改动）
  - 云端多租户运维形态

## 2. Research Findings
- 事实与约束:
  1. FileIO 缝（`src/harness/env.ts:34-37`）覆盖 9 个模块的行式日志读写；`nodeFileIO`（`src/app/env.ts`）为 Node 实现
  2. 绕缝直写 5 处：auth.ts:105（会话同步追加）、agents.ts:119-139 与 skills.ts:117-121（索引整文件重写）、tasks.ts:279-284（saveAll，调度器每 tick 触发）、notify.ts:88（markRead 重写）、server.ts:629/secretbox.ts/mcp.ts:109（读走缝写走文件的 last-line-wins blob）
  3. 同步热路径：conversations.ts:177/184/208（persona/agents 索引/skills 索引 readFileSync 每回合）、memory.ts:34（记忆槽 readFileSync 每回合）、auth.ts 会话签发同步落盘
  4. 九事件词表（`src/harness/session/events.ts`）：turn/start、turn/end、user/message、assistant/message、tool/call、tool/result、llm/retry、compaction/summary、request/header；seq append 时分配从 0 单调
  5. 账本四词表（`src/app/ledger.ts`）：event/plan/checkin/void，(uid 内) seq 单调，void 引用 target_seq，串行写队列
  6. 无文件 watch/tail/行偏移依赖；路径字符串是逻辑 ID（conversationIdOf 解析路径推导 cid）
  7. harness 零平台依赖铁律：不得直接 import node:sqlite
- 风险与不确定项:
  - node:sqlite 标 stability 1.1（experimental）→ 接受（自部署），接口收敛在 db.ts 单文件，可换 better-sqlite3
  - 13 模块重写工作量大 → 按 Checklist 分步，每模块测试同步改造保绿
  - WAL 备份需 checkpoint → ADR 0008 注明 VACUUM INTO

## 3. Innovate (Options & Decision)
### Option A：FileIO 缝换引擎（log_lines 通用表）
- Pros: 业务代码 0 改动、24 测试不动、工作量最小
- Cons: 仍是行透传，无强类型列；读模型保持全量载入
### Option B：领域表建模重写（13 张表）
- Pros: 强类型列、索引、SQL 按需查询（响应裁决②）、真正的数据建模
- Cons: 13 模块重写、测试改造、工作量大
### ~~Option C：混合（账本 JSONL + 其他 SQLite）~~：双真源，ADR 0007 已否决，不入选项
### Decision
- Selected: **Option B**
- Why: 用户明确裁决"我要领域表"+"不可以全量载入内存"；领域表同时消解五个绕缝直写点与两个同步热路径的结构性问题
- Innovate Skip: false（两方案已充分对比）
