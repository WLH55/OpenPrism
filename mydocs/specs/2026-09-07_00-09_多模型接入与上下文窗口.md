## 0. Open Questions

## 1. Requirements (Context)
- **Goal**: ① 模型配置支持"上下文窗口"自定义（喂给 harness 压缩器，替代 64K 默认值）；② 配置后展示"哪个平台 · 哪个模型"；③ 支持配置多个平台的模型并可切换/新增。
- **In-Scope**: model_providers/model_active 两张新表 + 旧 model_config 数据迁移；/api/models CRUD + 切换 + 测试端点；Settings 页改版（当前模型卡片 + 列表 + 新增/编辑表单 + 窗口预设）；conversations 传 contextWindow 给 createAgent。
- **Out-of-Scope**: 按模型路由（一次对话一个模型）；平台 OAuth；用量统计。

## 1.1 Context Sources
- 用户裁决（2026-09-07 聊天 + 截图）：加自定义配置项并在模型表单呈现；配置后显示平台与模型；可点击新增另一平台。
- 上游事实：`DEFAULT_COMPACTION.contextWindow = 64_000`（compact.ts:24），应用层建 Agent 未传 → 所有会话按 64K 判压。

## 2. Research Findings
- `createAgent` 合并顺序：DEFAULT_COMPACTION → config.model.contextWindow（有才覆盖）→ config.compaction；应用层只需把窗口塞进 `model: { provider, model, contextWindow }`。
- `model_config` 表 uid 单主键，无法多行 → 新表 `model_providers`（多行）+ `model_active`（uid→激活行）；旧 model_config 行需一次性迁移（现有生产库里 lathan 有一行 sk-demo）。
- 平台名从 baseURL 推导（deepseek→DeepSeek、bigmodel.cn→智谱 GLM、dashscope→通义千问…兜底 hostname）。
- Key 永不回传铁律不变：列表只回 hasKey。

## 3. Innovate
- Skipped: true（方案空间小：多行表 + 激活指针是唯一自然解；用户指令已定形态）

### 4.2 Signatures（核心）
```ts
export function platformFromBaseURL(baseURL: string): string
export interface ModelConfig { id?: string; platform?: string; baseURL: string; model: string; contextWindow?: number; keyEnc?: string }
export function addModelProvider(db, uid, input: { baseURL; model; contextWindow?: number | null; keyEnc?; platform? }): ModelConfig
export function updateModelProvider(db, uid, id, patch: { baseURL?; model?; contextWindow?: number | null; keyEnc? }): void

```
