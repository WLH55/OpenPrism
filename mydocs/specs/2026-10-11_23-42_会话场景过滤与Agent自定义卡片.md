## 1. Requirements (Context)
- **Goal**: 把 dsh-desktop 工作台设计的两条原则落到 OpenPrism：①「会话归属=语境切换」→ 给会话加**可选场景标签**，侧栏按场景过滤，获得"打开一个场景只见相关工作"的注意力隔离；②「用户用 Agent 扩展工作台本身」→ Agent（或用户在对话里）能创建/修改「今天」页的**自定义卡片**（固定 kind 枚举、配置驱动渲染），并把 dsh 规范里的「需求闸门」（场景/目的/更新方式不明就先问）搬进工具纪律。
- **In-Scope**:
  - A 线（场景过滤）：`conversations` 加可选 `scene` 列；场景目录从已打标会话动态长出（零预设，仿"分类即维度"无表方案）；侧栏场景 chip 过滤；打标入口
  - B 线（Agent 卡片）：widgets 新存储；agent 工具（创建/更新/删除/列表）；「今天」页"我的卡片"区块按 kind 枚举渲染；工具描述内嵌需求闸门
- **Out-of-Scope**: 插件系统与市场分发（ADR 0001 自用优先）；任意 HTML/代码渲染（只做固定 kind 枚举，配置经服务端校验）；盘面/成长页改动；微信桥行为变更；harness core（`src/harness/`）改动；卡片拖拽排序（后置 Follow-up）；卡片关联账本自动计算（后置 Follow-up）。
- **Acceptance Criteria**:
  - [ ] AC1 打过标的会话可被侧栏按场景过滤；"全部"视图不丢任何会话；微信/任务固定会话（`wechat:<uid>`、`feed:<uid>:<agent>`）行为不变
  - [ ] AC2 场景零预设、打标即建（无需先建目录）；目录随实际打标动态长出；最后一个打标会话取消后场景从目录消失（零残留）
  - [ ] AC3 Agent 在对话中经工具创建的卡片在「今天」页可见（刷新后），值可经工具/手动更新；非法 kind、超限字段、越权（他人 uid）被拒并以中文错误回话
  - [ ] AC4 工具创建/更新/删除结果照常入会话日志（model-visible means logged），`test/invariants.test.ts` 全绿
  - [ ] AC5 `pnpm test` + `pnpm typecheck` 全绿；工具契约断言（app-tools）与装配清单断言（app-conversations，现 13 工具）同步为 18 工具清单

## 2. Research Findings

### 2.1 A 线：会话存储与侧栏现状
- **表结构**：`conversations`（`db.ts:77-86`）列 = `cid PK / uid / title / agent_id / model_provider_id / pinned / switches_json / created_ts`，索引 `idx_conv_uid(uid, created_ts)`；无标签/分组机制。
- **加列先例**：`ensureColumn(db, "conversations", "pinned", ...)`（`db.ts:302-305, 426-427`），`PRAGMA table_info` 判存在再加，幂等——scene 列照此模式，一处改 openDb。
- **列表链路**：`GET /api/conversations` → `ConversationStore.list()`（`conversations.ts:151-157`），排序 `pinned DESC, created_ts DESC, cid`；返回 `{id,title,pinned,createdTs}`，**不含 agentId/scene**——需同步扩 SELECT 与两端类型（`conversations.ts:88-93`、`web/src/api.ts:30-35`）。
- **侧栏**：`SidebarContent`（`web/src/App.tsx:79-246`，桌面左栏与窄屏抽屉共用）；会话列表 `App.tsx:140-197`，现有唯一过滤 = 标题关键词客户端 filter（`App.tsx:160-161`）；固定会话已有"定时"chip（`App.tsx:175-177`）。chips 横滑先例 = 盘面分类 chip（`Panels.tsx:143-178`）。
- **固定会话语义**：`WECHAT_FEED_CID = wechat:<uid>`（`wechat-bridge.ts:31`，`ensureFeed` INSERT OR IGNORE pinned=1）；任务会话 `feed:<uid>:<agentId>`（`conversations.ts:164-182`）——两者是有固定 cid 语义的特殊会话，打标按普通会话对待（pinned chip 已区分身份）；微信通道与 web 共享同一会话，工具在两侧同权。
- **零预设先例**：盘面分类无独立表，`listCategories(records)` 从流水动态长出（`fold.ts:388-401`）——场景目录复刻此方案：目录 = 侧栏客户端从会话列表折叠 distinct scene，无表无管理面。

### 2.2 B 线：Today 页与工具注册现状
- **Today 页**：574 行全硬编码区块（快速记录表单 / Top3 卡 / 三统计卡 / 计划四范围 tab / 今日 flows），无配置驱动成分；数据源单一 `GET /api/today`（`server.ts:1046-1050` → `todayView`，`fold.ts:162-287`）。新区块插入点明确（三统计卡与计划 tab 之间）。
- **工具契约**：`ToolDefinition`（`src/harness/tools/registry.ts:15-33`）= name/description/parameters(JsonSchema)/output{schema,render}/execute/timeoutMs/isConcurrencySafe/concludeTurn；最小样例 `record_flow`（`src/app/tools.ts:29-74`）。装配在 `conversations.assemble()`（`conversations.ts:436-518`），受 persona 能力绑定白名单过滤（不设白名单默认全给）。
- **校验模式**：无 zod（零运行时依赖）——execute 内手写运行时检查 `throw new Error("中文报错")`，管线捕获归一为 isError tool/result 回话（`pipeline.ts:94-153`）；仅输出侧有自研 JSON Schema 子集校验（`src/harness/tools/schema.ts`）。
- **存储先例**：无通用 per-user kv/JSON 表；`archives`（uid 主键 + list_json，`db.ts:289-293`）是最近的 JSON 存储渲染先例；`meta` 是全局 kv 仅存迁移标记。widgets 需逐卡编辑/删除 → 新表逐行（照 archives 模式扩展）。
- **新增工具须同步 4 处**（2026-09-29_00-47 spec 先例）：`tools.ts` 文件头工具清单注释、`persona.ts` DISCIPLINE（`persona.ts:15-25`）、`test/app-tools.test.ts` 契约断言（工具名全列表）、`test/app-conversations.test.ts:201` 装配清单断言（现 13 工具）。
- **需求闸门可借鉴原文**：dsh workbench-standard 要求写码前确认"业务场景、目标用户、最小核心流程"，不明确就停在只读阶段——搬进工具 description 与 persona 纪律。

## 4. Plan (Contract)

### 4.0 批次划分（互相独立，可分别交付；W1 先行——更小、先拿注意力隔离收益）

- **W1 场景过滤**：scene 列 + setScene + 路由 + Agent 工具 + 侧栏 chip/打标 UI

### 4.1 File Changes

**W1（场景过滤）**
- `src/app/db.ts`：openDb 加 `ensureColumn(db, "conversations", "scene", "TEXT")`（紧邻既有 conversations ensureColumn 调用）
- `src/app/conversations.ts`：`ConversationEntry` 增 `scene?: string | null`；`list()` SELECT 增 scene；新增 `setScene(cid, scene | null)`（trim、非空校验 ≤32 字符、null=清空、cid 不存在或 uid 不符抛错）；新增 `createSceneTools()` 工厂（set_conversation_scene，作用于当前会话）并在 `assemble()` 注册（受 binding.tools 白名单）
- `src/app/server.ts`：`PUT /api/conversations/:cid/scene`（body `{scene: string|null}`，404/校验错误同既有路由风格）
- `src/app/persona.ts`：DISCIPLINE 增 set_conversation_scene 纪律（场景是用户的语境组织；新增/改标前说明；不擅自批量改）
- `web/src/api.ts`：ConversationEntry 类型 + `setConversationScene(cid, scene)`
- `web/src/App.tsx`：SidebarContent 加场景 chip 行（全部/未打标/各场景，`overflow-x-auto` 横滑，点选过滤与 convQuery AND）；会话项加标签按钮（输入框 + 已有场景 chips 快速选，空输入=清空）；新增场景打标后刷新列表

**W2（Agent 卡片）**
- `src/app/db.ts`：建 `widgets` 表（id TEXT PK / uid TEXT NOT NULL / kind TEXT NOT NULL CHECK IN ('note','progress') / title TEXT NOT NULL / payload_json TEXT NOT NULL / sort INTEGER NOT NULL DEFAULT 0 / created_ts INTEGER NOT NULL；索引 `idx_widgets_uid(uid, sort)`）
- `src/app/widgets.ts`（新）：`Widget` 类型 + `NotePayload/ProgressPayload` + `WidgetStore`（list/create/update/remove，uid 严格隔离；校验：kind 枚举、title trim 后 1–200 字符、note.text ≤2000、progress.target>0 且 value≥0 数值）+ `createWidgetTools(store, now)` 四工具（create_widget / update_widget / delete_widget / list_widgets；create_widget description 内嵌需求闸门；render 中文回执；isConcurrencySafe=false）
- `src/app/conversations.ts`：`assemble()` 注册 widget 工具（受白名单）
- `src/app/server.ts`：`GET /api/widgets`、`POST /api/widgets`、`PUT /api/widgets/:id`、`DELETE /api/widgets/:id`（auth uid 隔离）
- `src/app/persona.ts`：DISCIPLINE 增 widget 纪律（需求闸门原文式 + 卡片是驾驶舱不是便签墙，删前告知）
- `web/src/api.ts`：Widget 类型 + CRUD 函数
- `web/src/pages/Today.tsx`：三统计卡与计划 tab 之间插「我的卡片」区块——note 卡（标题+正文 pre-wrap）、progress 卡（value/target unit + 进度条封顶 100% + 数值照实）、就地编辑/删除（confirm）、空态一行引导（"在对话里让我建一张卡片试试"）；桌面 grid 多列、手机单列
- 相关注释同步：`tools.ts`/`conversations.ts` 文件头工具清单措辞

### 4.2 Signatures
- `ensureColumn(db, "conversations", "scene", "TEXT")`（db.ts 既有 helper）
- `ConversationStore.setScene(cid: string, scene: string | null): void`
- `ConversationEntry = { id; title; pinned; createdTs; scene?: string | null }`
- `createSceneTools(opts: { resolveCid: () => string | undefined; store: ConversationStore }): ToolDefinition[]` → `set_conversation_scene {scene: string|null}`
- `type WidgetKind = "note" | "progress"`；`NotePayload = { text: string }`；`ProgressPayload = { value: number; target: number; unit?: string }`
- `Widget = { id; uid; kind: WidgetKind; title; payload: NotePayload | ProgressPayload; sort; createdTs }`
- `class WidgetStore { list(uid); create(uid, input): Widget; update(uid, id, patch): Widget; remove(uid, id): void }`
- `createWidgetTools(store: WidgetStore, now: () => number): ToolDefinition[]` → create_widget / update_widget / delete_widget / list_widgets
- REST：`PUT /api/conversations/:cid/scene`；`GET/POST /api/widgets`、`PUT/DELETE /api/widgets/:id`
