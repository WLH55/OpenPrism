## 1. Requirements (Context)

- **Goal**: 让模型能撤任意历史打卡（凭据可查）；让 UI 用户能改计划（标题/截止日）与补历史卡——与 agent 工具侧能力对齐。
- **In-Scope**:
  1. `fold.ts` TodayPlanView：`doneSeqs` 语义修正——周期计划今日 done 也给「今日存活打卡 seq」（修复 UI 撤周期打卡不可用，对齐 Today.tsx:379 注释宣称的语义）；新增 `checkins?: { seq: number; at: number }[]`（最近 10 条存活 done 打卡，倒序，含非今日，全 scope 供给）。
  2. 工具侧描述：checkin_plan/void_flow 描述补「撤历史卡 seq 从 query_ledger today 的 checkins 拿」。
  3. 共享逻辑 `src/app/plans.ts`：`parseAt`（自 tools.ts 迁出）+ `mergePlanUpdate(cur, changes)`（部分更新校验+合并，返回 append payload）——工具与 UI 路由同源（goals.ts validateGoalParenting 同模式）。
  4. `server.ts`：`PUT /api/plans/:planId`（mergePlanUpdate + 追加新版本 + void 旧记录，source:"ui"）；`POST /api/checkin` 加 `date`/`time`（parseAt，未来拒绝）。
  5. `web`：api.ts 加 `updatePlan`、`checkin` 加可选 date/time；Plans.tsx 打卡点行加「编辑」（标题/due）；Today.tsx 计划行加「编辑」与周期计划「补卡」（选过去日期）。
  6. 测试：fold（doneSeqs 周期型/checkins）、server（PUT plans、checkin date）、tools（撤历史卡闭环）。
- **Out-of-Scope**:
  - 时区统一（用户档案时区方案已议定，待用户确认后另开 spec）。
  - goal 真删工具、UI 补卡对 deadline 型（打卡即完成，补历史无意义）。
  - update_plan 工具本身（上轮已交付）。
- **Acceptance Criteria**:
  - [ ] AC1 today 视图：周期计划今日 done → `doneSeqs` 含今日打卡 seq；任何有存活打卡的计划 → `checkins` 列最近 ≤10 条（倒序，含非今日）。
  - [ ] AC2 模型撤历史卡闭环：query_ledger today 取某计划 checkins 中非今日的 seq → void_flow(seq) → 该打卡作废（如周一打卡撤后周期「进行中」判定回退）。
  - [ ] AC3 `PUT /api/plans/:planId`：改标题/due 后 GET /api/today 的 plans 反映新值、planId 不变、旧 plan 记录被 void；与 update_plan 工具共用 mergePlanUpdate（同源断言：两侧改同一计划结果一致）。
  - [ ] AC4 `POST /api/checkin` 带 date：at 落指定当地日；未来日期 400。
  - [ ] AC5 UI：计划页打卡点可编辑标题/due；今天页计划行可编辑、周期计划可补卡（date input 选过去日期，补后今日/周期判定正确刷新）。
  - [ ] AC6 `pnpm test` + `pnpm typecheck` 全绿；前端 `pnpm -C web build`（或既有构建检查）通过。

## 2. Research Findings

- 事实与约束:
  - `fold.ts:170`：doneSeqs 仅 `scope==="deadline" && state==="done"` 时给出；`Today.tsx:340` `undoable = plan.done && doneSeqs.length>0` → **周期计划今日 done 不可撤销**，而 `Today.tsx:379` 注释宣称「周期=今日打卡」可撤——实现与注释不符，本轮顺带修复。
  - `Plans.tsx:117` MilestoneRow 根元素是 `<button>`（HTML 不允许嵌套 button）——加「编辑」入口需重构为 div+click 语义（保留 disabled 表现与 title 提示）；`Today.tsx:369` 计划行已是 div，可直接内嵌按钮（stopPropagation，同「跳过」按钮先例 :404-415）。
  - `server.ts /api/checkin`（995-1010）at 固定 `deps.env.now()`；`/api/plans`（1038-1062）仅 POST——UI 无修改计划路由。
  - `Plans.tsx` 的 milestones 与 doneSeqs 来自 `GET /api/goals`（server.ts:1020-1034 全量存活 done seq）——与 today 视图的 doneSeqs 是两个来源，本轮只改 fold.ts 的 today 口径，/api/goals 不动。
  - tools.ts 的 update_plan 合并逻辑在工具闭包内，server 无法复用——提取纯函数共享；parseAt 同迁。
  - web 无前端测试基建（test/ 全后端）——AC5 为实现+手验，AC6 以构建通过为底线。
  - todayView 的 checkins 需限制条数防上下文/载荷膨胀：最近 10 条（倒序）。
- 现状链路: 工具装配（conversations.ts）与 UI 路由（server.ts）都从同一 Ledger 实例读写；折叠层（fold.ts）单一真相。
- 风险与不确定项:
  - doneSeqs 语义扩展改变 Today.tsx 周期行点击撤销行为（从无效变有效）——正是目标，但需回归既有用例。
  - MilestoneRow button→div 重构需保键盘可达性（tabIndex/role/Enter 键）——按现有样式最小实现。
  - mergePlanUpdate 抽取时 update_plan 工具行为必须零变化（同源重构，既有 13 用例守护）。

## 3. Innovate (Optional: Options & Decision)

### Option A
- 方案: doneSeqs 语义扩展（=「当前可撤销的打卡 seq」：deadline 全量存活 done / 周期今日 done）+ 新增 checkins（最近 10 条 {seq, at} 全 scope）。
- Pros: UI 撤周期打卡零改动自然修复；模型撤历史卡有带时刻的凭据可分辨是哪天。
- Cons: doneSeqs 含义从「deadline 完成凭据」变为「可撤销集合」——需同步 fold.ts 注释与 UI 注释。
### Option B
- 方案: 只加 checkins，不动 doneSeqs。
- Pros: 改动更小。
- Cons: UI 撤周期打卡依然不可用（实现/注释不符不修复），本轮目标 2 半残。
### Decision
- Selected: Option A。
- Why: checkins 的 at 让模型能定位「周一那条」；doneSeqs 扩展一次修复 UI 缺口且与既有撤销代码路径（for seq of doneSeqs voidRecord）完全兼容。
