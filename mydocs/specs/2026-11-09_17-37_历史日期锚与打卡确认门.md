## 1. Requirements (Context)
- **Goal**: 2026-11-09 真机事故：模型凭无时间戳的历史推断用户今天练完了拉日，自行调 checkin_plan 打卡并在 12:15 简报里报「刚打完卡」，用户实际没练。
- **In-Scope**:
  - 投影层给每条用户消息确定性注入日期锚行 `〔YYYY-MM-DD 周X〕`（事件 ts + 会话时区推导，日志原文不动）。
  - AgentConfig 新增 `dateAnchorTz?: () => number` 通道，conversations 装配按会话时区接线。
  - persona 纪律文本与任务会话规则加「事实性写入确认门」；TASK_FEED_RULES 的「按假设完成」加例外。
  - checkin_plan 工具描述加确认门。
  - 确定性测试覆盖投影、接线、提示词文本。
- **Out-of-Scope**:
  - 日志事件结构（ts 已存在）、前端 UI、压缩摘要格式。
  - checkin_plan 同日重复卡去重等工具行为变更。
  - zcode 式滑动尾部窗口等上下文长度治理（本项目已有压缩机制）。
- **Acceptance Criteria**:
  - [ ] AC1 传了时区的投影：每条 user/message 在模型可见面带当日日期锚；assistant/message 与 tool_result 不带；各消息正文与块结构不损。
  - [ ] AC2 时区换日正确：UTC 时刻 + 偏移跨日时锚落次日；不传时区 = 行为与现状逐字节一致（向后兼容，harness 既有测试零改动通过）。
  - [ ] AC3 纯附件消息（无 text 块）锚以独立 text 块注入。
  - [ ] AC4 conversations 装配把用户时区喂进锚（mock 请求里能看到两天的锚不同）。
  - [ ] AC5 纪律文本、任务会话规则、checkin_plan 描述三处均含确认门表述；任务规则的「按假设完成」对事实性写入有例外句。
  - [ ] AC6 `pnpm test` 全绿 + `pnpm typecheck` 0 + `pnpm build:web`；提交、部署、健康检查通过。

## 2. Research Findings
- 事实与约束:
  - `projectSurface`（project.ts:77）对 user/message 只取 `event.message`；事件公共字段含 `seq` 与 `ts`（events.ts:96-97）。
  - 回合上下文（〔系统上下文〕钟面行）只并入最后一条带 context 的用户消息；历史消息在 wire 上无任何时间信息。
  - 时区口径：`deps.tzOffsetMinutes?.(uid) ?? -new Date().getTimezoneOffset()`（conversations.ts turnContextFor）；dateLine 用纯 UTC 位移算日期星期，harness 可复用同法（零平台依赖）。
  - invariants.test.ts 断言「wire == deriveMessages(日志前缀)」用缺省参数——harness 级双向都不带锚即自洽；app 层无投影重建断言。
  - TASK_FEED_RULES 现文「按最合理的假设完成本次提醒」是模型抢答打卡的直接授权；DISCIPLINE 只要求写入走工具，无确认要求；checkin_plan date 缺省今天。
- 现状链路: taskRunner/微信/web → followup → buildRequest → projectSurface 全量回放（无锚）→ 模型分不清哪天的对话 → 按历史模式假设今天已完成 → checkin_plan 缺省落账。
- 风险与不确定项: 锚行增加少量 token（每回合约 15 字符）；压缩遮蔽区间内的锚随区间一起消失（摘要可含日期，不另处理）；时区在 agent 池驻留期间以函数每回合现读（与钟面同口径，无过期问题）。
