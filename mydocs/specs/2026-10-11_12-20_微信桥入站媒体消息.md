## 1. Requirements (Context)

- **Goal**:
  1. **图片**：微信发图 → CDN 下载 + AES 解密 → base64 `ImageBlock` 进「微信对话」会话回合 → 多模态模型识图 → 回复推回微信（web 端同一会话同步可见图片）。
  2. **文件**：微信发文本类文件 → 下载解密 → 正文内联 `FileBlock` 进回合；二进制文件明确告知不支持（与 web 上传口径一致）。
  3. **语音**：协议自带转写文本 → 按文本消息进回合（不下载音频）。
  4. **保活修复（附带）**：媒体消息也刷新 `last_context_token`/`last_msg_ts`——现状图片在 getUpdates 层被丢，不能给 12h 推送窗口续命。
- **In-Scope**:
  - `ilink.ts`：getUpdates 解析 item_list 全量类型（1/2/3/4；5=video 忽略+日志）；`ILinkInboundMessage` 扩媒体字段；新增 CDN 二进制下载方法。
  - `wechat-media.ts`（新）：AES key 三格式解析、AES-128-ECB 解密（容错 PKCS#7）、图片 magic bytes 嗅探、文本文件探测——纯函数 + node:crypto（仅 app 层）。
  - `wechat-bridge.ts`：handle() 媒体下载 → `ContentBlock[]` → `conversations.send(text, attachments)`；失败分类处理（不跑回合、直接 push 说明、不进轮询退避）。
  - `env.ts`：`EnvFetchResponse` 加可选 `arrayBuffer()`（纯类型扩边，真实 Response 原生满足）。
  - 文案：欢迎语与 IM 页提示补媒体能力说明。
  - 测试：fake iLink 扩二进制响应；测试内用 node:crypto 确定性构造密文。
- **Out-of-Scope**:
  - 出站媒体（机器人回图/回文件）——iLink sendmessage 只发文本，协议未摸。
  - 视频（type=5）——WeKnora 亦无 video_item 结构定义，忽略。
  - 语音音频本体下载/识别——只用协议自带转写文本。
  - 二进制文档解析（PDF/Office）——与 web 上传口径一致，显式拒绝。
  - 群聊、多会话路由。
- **Acceptance Criteria**:
  - [x] AC1 图片闭环：微信发图（fake iLink 下发 image_item + CDN 密文）→ mock LLM 收到 `image_url` data URL 块 → 回复推回微信；web 同会话日志含 ImageBlock。
  - [x] AC2 文本文件：file_item（txt/md 等）→ 下载解密 → FileBlock 内联正文进回合；二进制文件 → 不跑回合、push「暂不支持二进制文件」说明。
  - [x] AC3 语音：voice_item 带转写 → 按文本进回合；转写为空 → 不跑回合、push「没能转写」说明，**但仍刷新上下文锚**（为此 voice 以 media 项（kind=voice, voiceText）过桥而非在 getUpdates 并入 text——空转写消息不能被丢弃，见 §8）。
  - [x] AC4 保活：任一媒体消息（含下载失败的）都刷新 `wechat_binds.last_context_token/last_msg_ts`。
  - [x] AC5 失败不毒丸：CDN 下载失败 / 解密失败 / 图片超 6MB / 模型非多模态 → 该条消息得到说明性 push，同批后续消息照常处理，轮询循环不退避中断。
  - [x] AC6 回归：`pnpm test` / `pnpm typecheck` 全绿；既有文本路径行为不变（420 用例基线）。

## 2. Research Findings

- **iLink 媒体协议（WeKnora 事实源，无公开文档）**：
  - `item_list[].type`：1=文本 2=图片 3=语音(自带转写) 4=文件 5=视频（无结构定义）。
  - `image_item { media: { encrypt_query_param, aes_key }, aeskey, url? }`——注意 `aeskey` 是**顶层 hex 字符串（32 字符 = 16 字节）**，json tag 为 `aeskey` 非 `aes_key`；`media.aes_key` 为 base64。图片优先用顶层 `aeskey`。
  - `voice_item { media, text }`——`text` 即语音转写结果，无需下载。
  - `file_item { media, file_name, len }`——`len` 是**字符串**形式的明文字节数。
  - CDN 下载：`GET https://novac2c.cdn.weixin.qq.com/c2c/download?encrypted_query_param=<urlencoded>`——**无鉴权头**（WeKnora DownloadFile 裸 GET）。
  - AES key 三种线上格式（parseAESKey 自动探测）：raw hex 32 字符 / base64(16 裸字节) / base64(32 位 hex ASCII)。
  - 解密：AES-128-ECB + PKCS#7 **容错**剥离（WeKnora 实现「像 padding 才剥」，密文可能无 padding）。
  - WeKnora 只取 `item_list[0]`；本实现改为遍历全部条目（文本+图片混排两不误）。
- **本仓库就绪面**：
  - `conversations.send(uid, cid, text, attachments)`：附件含图 → `modelConfigFor().multimodal` 校验，非多模态抛 `ModelNotMultimodalError`（**不消耗回合**）；空文本 + 纯附件合法（content 只剩附件块）。
  - `ImageBlock { mediaType, data(base64) }` → openai-compat 拼 `image_url` data URL；`FileBlock` → wire 文本内联（plainTextOf 的 `【附件 name】` 抬头）；图片入会话日志 → model-visible 不变量自动满足（铁律 2）。
  - `attachments.ts` 限制常量与签名校验（matchesSignature 防错标）可直接复用口径：图片 ≤6MB/条、≤4 张/消息、合计 ≤12MB、文本 ≤400k 字符。
  - 真实 `env.fetch` 直通原生/undici Response（`arrayBuffer()` 原生存在）——接口加可选方法即全兼容。
- **现状缺陷链（本 spec 修的对象）**：
  - `ilink.ts:157-159` 只取 type=1 文本，无文本整条丢弃 → 媒体消息不进会话、不刷上下文锚（保活盲区）、无任何日志或回执。
  - `wechat-bridge.ts:229` `send(uid, cid, msg.text)` 第 4 参缺省 → 即便解析了媒体也进不了回合。
  - `EnvFetchResponse` 无二进制读取面（只有 json/text/body 流）。
  - handle() 无错误分类：`ModelNotMultimodalError` 等会直接抛进 pollOnce → loopInternal 退避循环，中断同批后续消息（毒丸）。
- **风险与不确定项**:
  - iLink 无公开文档：CDN 响应形态（Content-Type、是否 302 跳转）以 WeKnora 为准（裸 GET + 200 直读 body）；真机偏差按母 spec 惯例 §8 留痕回改。
  - 图片实际格式未知（WeKnora 盲命名 .png）：解密后嗅探 magic bytes 定 mediaType，不在 PNG/JPEG/WebP/GIF 白名单则按「不支持该图片格式」处理。
  - 微信「文件」消息可能是任意类型（含大文件）：`len` 先验 + 密文硬顶 17MB + 用途各自限额，超限直接说明不下载/不解。
  - ECB 模式 Node `createDecipheriv("aes-128-ecb")` 原生支持；padding 用 `setAutoPadding(false)` + 手工容错剥离，与 WeKnora 语义一致。

## 2.1 Open Questions

- [x] Q1 失败策略（下载失败/超限/二进制/非多模态模型）→ **不跑回合、直接 push 说明文本**（transport/配置错误不是对话内容；跑回合 agent 也只能说「看不到」），且 catch 后继续处理同批后续消息，不进轮询退避。依据：这些错误重试无意义（cursor 已推进，消息不会重拉），退避反而伤后续消息。
- [x] Q2 解析范围 → 遍历 item_list 全部条目（WeKnora 只取首条），文本/图片/文件/语音转写按序合并为**一次回合**；type=5 视频忽略并 `console.warn`。
- [x] Q3 附件限制口径 → 沿用 attachments.ts 常量（6MB/4 张/12MB/400k 字符），wechet 侧超限走 Q1 说明路径（web 侧是 400 异常，微信侧是对话内说明，同一套数值）。
- [ ] Q4（真机项）CDN 响应是否带 Content-Disposition/扩展名、图片真实格式分布、aeskey 字段线上形态（hex 顶层 vs media.aes_key base64 哪种为主）→ 部署后实测补记 §8；代码按三格式全兼容写。

### 4.2 Signatures

- `interface ILinkMediaItem { kind: "image" | "file" | "voice"; encryptQueryParam: string; aesKeyRaw: string; fileName?: string; sizeBytes?: number; voiceText?: string }`（voice 以 media 项过桥：voiceText = 协议转写文本，可为空串 = 转写失败；encryptQueryParam/aesKeyRaw 对 voice 可空——音频不下载）

- `buildCdnDownloadUrl(encryptQueryParam: string): string`（`https://novac2c.cdn.weixin.qq.com/c2c/download?encrypted_query_param=` + encodeURIComponent）
- `ILinkClient.downloadMedia(url: string): Promise<Uint8Array>`
- `parseAesKey(raw: string): Buffer`；`decryptAes128Ecb(ciphertext: Uint8Array, key: Buffer): Buffer`；`sniffImageType(bytes: Uint8Array): ImageMediaType | null`；`decodeTextFile(bytes: Uint8Array): { ok: true; text: string } | { ok: false }`
- bridge 私有 `mediaToAttachments(uid: string, msg: ILinkInboundMessage): Promise<{ blocks: ContentBlock[] } | { failure: string }>`（failure = 已成型的面向用户的说明文本）
