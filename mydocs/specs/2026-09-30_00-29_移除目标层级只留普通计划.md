## 1. Requirements (Context)
- **Goal**: 用户明确不要长期方向/阶段/项目/打卡点这层抽象了。产品收敛为：AI 对话 + 普通 计划（周期/截止）+ 打卡 + 流水 + 定时提醒。已挂在树上的 deadline 计划必须无损降级为独立计划（planId/打卡史不变）。
- **In-Scope**:
  - 后端：删 create_goal / update_goal / delete_goal 工具；query_ledger 去 what=goals 与 goalId 过滤；create_plan/update_plan 去 goalId 参数；fold 删 goalView/goalCard/里程碑补位/goalTitle；server 删 /api/goals 全套路由与 plan goalId 校验；persona 提示词与内置三件套指令去目标话术
  - 前端：删 Plans 页（目标树页）与导航项；Today 页去「属于：xx」；Progress 页删方向进度卡；api.ts 清类型
  - 测试：goal 相关用例删除/改写，工具清单 16→13
- **Out-of-Scope**:
  - 账本里既有 goal 行/void 行：**原样保留**（append-only 历史，功能面全撤后自然不可见不可写，不做迁移不做清洗）
  - 已挂树计划的数据处置：goalId 字段保留在历史行里，投影层忽略 → 自动变独立计划（零迁移）
  - 内置定时任务三件套的触发机制、记账/流水、记忆、微信桥：不动
- **Acceptance Criteria**:
  - [ ] AC1 工具装配清单 = 13 件（cancel_plan/checkin_plan/create_plan/create_task/delete_task/query_ledger/query_tasks/record_flow/save_preference/search_memory/update_plan/update_task/void_flow），无任何 goal 工具
  - [ ] AC2 create_plan/update_plan 不再有 goalId 参数；旧对话若传 goalId 收到明确报错「目标层级已下线」而非静默忽略
  - [ ] AC3 query_ledger what=goals 报未知视角错；today/plans/flows 三视角回执不带任何 方向/阶段/goalCard 字样
  - [ ] AC4 服务器真实数据下：原挂树计划（goalId 非空的历史 deadline 计划）在今天页/计划查询中正常出现、可打卡、状态机正确（用现有 uid 折叠验证）
  - [ ] AC5 Web 无「计划」导航项（目标树页整页删除）；今天页无「属于：xx」；成长页无方向进度卡；web tsc + vite build 通过
  - [ ] AC6 内置三件套指令文案不再引用 goalCard/what=goals/方向/阶段（grep 零命中）
  - [ ] AC7 pnpm test / pnpm typecheck / web 双检全绿；服务器部署后 /api/health ok
