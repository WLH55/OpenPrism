## M0 根动机与形态（Q1，2026-09-01 已确认）

**脱离 dsh 宿主，做安卓原生 App；自用优先、尽快可用；本库代码全部删除重写。**
- 真实驱动 = 「自己每天在手机上随手记录与查看」：插件形态要求桌面常开 dsh 宿主（Node 进程 + 会话日志 + web UI + profile），与手机使用形态根本冲突。
- 复刻 dsh-agent-loop / dsh-agent / dsh-llm 的**代码**与安卓目标互斥（Node ESM、`node:crypto`、cordis 插件运行时跑不进安卓）；复刻对象重新定义为**设计模式**：事件溯源式仅追加日志、provider 中立的 LLM 抽象、回合循环 + 工具派发。
- 否决：继续插件路线（绑定桌面宿主）；Node 服务端 + 手机客户端（要养常开机器，组网负担同 2026-08 D9 的排除理由）；WebView 壳（D9 已否决，后台/离线最弱）。

## M1 技术栈（Q2，2026-09-01 已确认）

**Expo (React Native) + TypeScript，单码库单语言。**
- 现有技能 TS/React 直接平移：React 组件与 hooks 照写，渲染目标从 DOM 换成原生控件；RN 是真原生渲染，非网页套壳。
- Expo SDK 提供全部所需原生模块（filesystem / secure-store / notifications / background-task），零 Java、零 Gradle；自用分发 = sideload APK，不上架。
- 否决：Kotlin + Compose（全栈新语言，交付最慢）；Flutter + Dart（无 TS 增量）；Capacitor 壳（同 M0 否决理由）。

## M2 代码命运与规格延续（Q3，2026-09-01 已确认）

**本库代码全部删除重写；git 历史与 docs 保留；领域模型按 ADR 0002/0003 规格在新代码中重新实现；旧 `~/.dsh/openprism/events.jsonl` 可选导入。**
- 探查事实：dsh 全量约 21.8 万行；目标三包的传递闭包 10 包 21,558 行（其中 dsh-tools 7,727 行为用不到的工具实现）；插件 src/ 里 13 个文件约 2,100 行零 dsh 依赖。用户拍板：**不移植任何旧代码**，全部重写。
- 规格照搬的理由：六个批次 + 68 项测试打磨出的仅追加 / 更正链 / 双时间戳 / 折叠语义，重 derive 只是重踩坑；规格是文档（ADR）不是代码。
- **镜像器与 rebuild 蒸发**：它们存在的唯一前提是数据源头活在格式不受控的 dsh 会话日志里；App 自有会话后，工具执行直接落事件日志（带 `source: conversation` + `sessionId` 溯源），无需镜像与重建。

## M3 存储选型（Q3 附，2026-09-01 已确认）

**文件系统 + JSONL 为正典（事件 / 会话 / 简报），SecureStore 存 API key，MMKV 存界面设置；不上 SQLite，但存储收在窄接口之后。**
- 工作负载 = 仅追加 + 全量折叠（沿用 2026-08 纪要 3.2 的量级论证：个人一年几千条，折叠毫秒级），索引查询无用武之地；更正也是追加，行更新能力同样用不上。
- 数据主权：一个 JSONL 文件就是全部数据——导出/备份即分享文件、旧数据迁移即拷贝、出问题人工可读。简报本就是 markdown 文件。
- SQLite 的两个真优势（拷问中摆明）：**崩溃原子性**（App 被杀留下撕裂尾行）与**无头任务的独立 JS 上下文并发追加**（旧 ADR 的单实例假设在安卓第二批后被削弱）。对策：追加全部收敛到存储模块的串行队列 + 加载器容忍并修复撕裂尾行；dsh 本体会话日志亦为文件（zstd jsonl），更重负载下有先例。
- 保险：EventStore 窄接口（`append` / `loadAll`）隔离实现；真机验证若出现损坏或并发问题，SQLite 作为同接口替换后端插入，JSONL 永远保持导出/迁移的交换格式（「物化层是可丢缓存」哲学允许此演进）。

## M4 指令与定时任务（Q4，2026-09-01 已确认）

**定时任务 = {时刻表， 自然语言指令}；到点在无头会话中执行指令（带全部录入与查询工具），产物存档 + 本地通知。**
- 指令是自然语言而非 shell/脚本：零代码、与对话共用同一套工具与提示词。例：「每周一 8 点总结上周支出，超预算要提醒我」。
- 安卓现实约束：doze / OEM 杀后台使「精确到点」不可承诺——可靠性以**补跑**为主（App 打开时补执行错过的任务，对齐 2026-08 简报补跑语义），精确闹钟（需用户授权）为尽力而为增强。
- 否决：预制命令菜单（做不到「自定义」）；shell 命令（安全面 + 表达力倒退）。

## M5 交付切分（Q5，2026-09-01 已确认）

**两批交付。第一批：对话录入六维度 + 面板 + 厂商配置 + 手动简报；第二批：定时任务 + 本地通知投递。**
- 第一批结束即可开始日常真实使用（成品验收方式不变：作者日常真实使用）。
- 定时任务放第二批的原因：安卓后台行为必须真机验证，不该卡住第一批；无头会话所需的基础（agent 循环脱离 UI 运行）在第一批就位。
- 采集/提炼管线（always-record → 夜间提炼）与连接器（Chatlog、微信通道）列为后续演进，不进前两批。

## M6 引擎与记忆边界（Q 附，默认采纳）

- **OpenAI 兼容客户端**（约 400 行）：流式 + 工具调用；provider 中立错误识别照搬 dsh-llm 规格（上下文超限 / 欠费 / 凭证无效统一归类，适配器只需翻译厂商错误文案）。
- **agent 循环**（约 300 行）：消息 → 工具调用 → 执行 → 回灌，多轮直至收敛；不依赖 UI，前台会话与无头会话共用同一循环。
- **记忆边界**（拷问澄清）：会话内记忆 = 消息历史（超长时摘要压缩，不搬 dsh 全套 compaction 机器）；跨会话生活记忆 = 事件日志折叠 + 面板查询工具。引擎与记忆分离，不造第二份记忆系统。

## M7 厂商配置（Q 附，默认采纳）

**通用 OpenAI 兼容适配：{名称, baseURL, apiKey, 模型清单}，内置厂商预设（DeepSeek / GLM / Qwen / Moonshot / OpenRouter…），key 存 SecureStore、不上传任何地方。**
- OpenAI 兼容协议覆盖绝大多数厂商，一个适配器全搞定；特殊协议厂商（如 Anthropic 原生）真需要时再加适配器。

## 架构总览

```
对话 UI（RN）─▶ agent 循环 ─▶ OpenAI 兼容客户端 ─▶ 各厂商 API
                   │ 工具执行（录入 / 更正 / 目标 / 面板查询）
                   ▼
        事件日志（events.jsonl，App 私有目录，唯一持久层）
                   │ 折叠（更正链 / 改名链 / 目标进度）
                   ▼
         面板 UI / 简报 markdown / 无头任务产物
```
