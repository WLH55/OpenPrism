## D1 应用定位与支柱（Q1，2026-09-03 用户自述确认）

**个人 AI 伴侣应用：记录生活、监督进步、陪伴聊天；支持自定义多个智能体（人设 / 可安装技能 / 远程 MCP 工具），全部智能体共享对用户的长期记忆。**

四大支柱：

1. **记录生活**——对话即录入，聊天中提到花钱、心情、做了什么，模型调工具落账。
2. **监督进步**——计划/待办（今日/本周/本月/今年/最近 N 天/带截止日）+ 自定义定时任务到点主动通知（如"每晚 23:00 提醒睡觉""每天检查今日学习任务"）+ 打卡闭环。
3. **陪伴聊天**——多智能体，自定义人设语气（openclaw 的"庄丽洪学姐"式人设是典型用例）。
4. **长期记忆**——跨会话、跨智能体记住用户这个人（身份、偏好、长期目标、对风格的反馈）。

### openclaw 实践的机制教训（本定位的直接依据）

用户此前用 openclaw 搭过同类助理（灵活性极高：可读写本地任意文件），暴露三个痛点，新架构必须有结构性解药：

- **"AI 不听话、数据丢失"**：让模型自由手写 markdown 文件当数据库 → 记录静默丢失、积累不完整。教训：录入的唯一途径是**工具**（参数 schema 校验、失败 isError 可见），持久层是**只追加日志**（写成功即落事件，机制上不存在静默失败）。harness 的工具管线与会话/事件日志天然满足。
- **"没有统计面板"**：数据埋在文件表格里，无法随时查看。教训：面板 = 事件日志上的**确定性折叠**（零 token、不怕模型算错）——2026-08 纪要的面板/简报规格可整体继承。
- **量化复利感是核心情感诉求**："升级打怪、人生不断复利"。统计设计的目标不是全面，而是**让进步可见**——连续、完成率、趋势、对照四个可计算指标足够，不发明等级/经验值系统。
- **人设文档 ≠ 生活数据**：IDENTITY/SOUL/AGENTS/TOOLS 属**智能体配置**（→ Q3），USER/MEMORY/HEARTBEAT 属**长期记忆**（→ Q4）——结构化存储、注入 system prompt，不依赖模型自觉读文件。

## D2 数据原语（Q2，2026-09-03 默认采纳，可推翻）

**提议：应用的数据宇宙共 5 类，其中真正要新设计的"生活数据"原语只有 3 类。**

> **2026-09-28 增补（SDD 个人工作台业务借鉴）**：新增第 4 类生活数据原语**目标（goal）**——方向/阶段/项目三层层级，plan 经 goalId 挂树（等价外键），修订 = 追加同 goalId 新快照（最新胜出，不消耗 void），层级/环校验见 src/app/goals.ts。原 3 类判断基于"生活长尾记不完"——goal 不是记录长尾而是用户自建的目标结构，不违反零预设（结构自建、无预设内容）；数量约束为软提示不 block。里程碑不设新原语：挂树的 deadline 型 plan + 打卡即里程碑。

| 原语 | 记什么 | 来源 |
|---|---|---|
| 流水（event） | 发生了的事：支出、心情、睡眠、运动、体重……带时间 + 自由分类（零预设）+ 可选数值/备注 | 聊天落账、采集管线（继承 2026-08 Q5 规格） |
| 计划（plan） | 打算做的事：任意周期（日/周/月/年/最近 N 天/截止日），可带目标量；习惯 = 重复计划 | 用户主动设置（菜单/对话） |
| 打卡（check-in） | 对某条计划的执行申报：完成/部分/跳过，可带数值 | 用户主动说、定时任务追问后回答、面板勾选 |
| 对话（conversation） | 陪伴聊天本身 | harness 已有（会话日志+压缩+恢复），零新增 |
| 记忆（memory） | 关于用户的持久事实 | Q4 专章设计 |

关键区分：**流水记"发生了什么"，打卡证"打算做的做了没"**——没有对应计划的运动是流水，对"周三运动"计划的申报是打卡。openclaw 的 habits/daily/weekly/monthly/yearly 五层文件统一为"计划 + 周期属性"，不再五套文档。记错更正回路继承 2026-08 Q4 规格。

### 2.1 原语的结构：结构定死、内容自由（2026-09-03 提议）

**不建关系库：唯一持久层仍是 JSONL 只追加日志（继承 2026-08 D3.2），面板/表都是从日志折叠的内存视图；"定死 vs 自由"指的是工具写入时的 schema 校验范围。**

- 定死（折叠要读的骨架）：kind、时间、数值、单位、计划引用、打卡状态——schema 校验，缺失即 isError 拒绝。这是"AI 不听话丢数据"解药的本体。
- 自由（只有人和模型读的肉）：分类名（纯字符串、零预设、随口建）、备注、扩展袋 `attrs`（自由键值）。
- 自由轴不参与统计；某 attr 用久了要看曲线，走显式"晋级"成一等数值字段，不做万能字段爆炸。
- 自定义记录类型不设新原语：分类 + attrs 即自定义类型系统（"读书" = 流水 + category"读书" + attrs{书名,页数}）。
- 打卡 → 计划 的引用完整性由工具校验保证（等价外键，无数据库）。
- schema 演化：只追加日志下旧事件永远合法；加字段 = 加可选字段 + 折叠认旧认新，无表可迁移。

否决的极端：全定死（生活长尾枚举不完，固定列爆炸或退化成万能 value 列，且预设字段违反零预设铁律）；全自由（= openclaw markdown 失败模式，折叠不可行，回到模型猜数）。

### 2.2 账本与会话文件的关系：多对一汇流（2026-09-03 提议）

**生活账本全局唯一（每用户一本 data/life.jsonl），与会话文件是多对一：所有会话的工具落账、面板手动操作、定时任务产物全部汇入同一本。**

- 会话文件（一个会话一个，harness 现成机制）只管对话本身；账本只管生活数据；统计跨全部会话折叠。
- 工具调用是两本账之间的桥：会话里的 tool/call + tool/result 是录入凭据（可溯源），账本里那条是数据本体。
- 每条账带来源标记（chat / ui / schedule）；chat 来源可从会话日志重放重建，ui/schedule 原样保留——继承 2026-08 D3.3 rebuild 语义，防双真源漂移。
- 面板是完整写入方（手动登记 / 勾打卡 / 编辑 / 删除，source: ui）；编辑与删除 = 追加更正/作废事件而非原地改行（继承 2026-08 Q4 更正回路），折叠时应用更正、滤掉作废——账本永不原地修改，历史留痕，聊天更正与面板编辑共用同一更正原语。
  - **2026-09-04 落地补全**：聊天侧更正原语此前只有 UI 入口、模型无工具可调；补 `void_flow`（按 seq 作废流水）与 `cancel_plan`（按 planId 作废计划），`query_ledger` flows 输出补 seq 作引用凭据——"聊天更正与面板编辑共用同一更正原语"至此真正对等。
- 多智能体各开各的会话文件；账本与记忆（Q4）全局共享——生活与"用户这个人"都是同一个人的一份。

### 2.3 账本的读写与并发（2026-09-03 提议）

**追加写 O(1)；读 = 启动全量载入内存、面板只读内存；写 = 单进程内一条串行队列。**

- 量级：一天 ~20 条 → 十年 ~7 万条 ≈ 20MB，启动全量解析百毫秒级，面板折叠毫秒级。
- 写队列（异步互斥）：对话工具 / 面板操作 / 定时任务全部排队串行追加，每条带自增序号，顺序确定、无交错；内存账本同队列同步，读写不竞争。**串行的是"追加一行"的瞬间（毫秒级），不是对话**——多对话/多智能体的回合与工具执行完全并行，仅落账排队；统计按账内时间戳算，先后落账不影响结果。
- 单进程单实例假设（继承 2026-08 同款）：多进程同时写真冲突，个人 App 场景排除；真需要那天加文件锁。
- 崩溃自愈：只追加最坏撕裂最后一行，丢弃即可；chat 来源可从会话日志重放重建（2.2 凭据机制）。
- 逃生门（真膨胀再启用）：尾部增量加载 / 快照缓存，属"真慢了再加"。

### 2.4 每用户一本：目录命名空间（2026-09-03 提议）

**账本定义域从"每设备"扩为"每用户"：data/users/{uid}/ 下每用户一个完整沙盒（账本 + 会话 + 记忆 + 智能体配置），互不干扰。**

## D2b 用户体系与部署形态（Q2b，2026-09-03 用户确认）

**做登录注册，开放给他人使用：公网多租户服务 + 用户可自部署（本机/局域网）。三种部署共用同一核心**（harness 零平台依赖纯 TS 库，服务器/本地同构）：

- 个人自用 = 自部署最小形态（本机跑同一服务）；
- 局域网自部署 = 同一二进制跑在家用设备，浏览器访问；
- 公网多租户 = 同核心 + 登录注册 + 账号隔离 + 云端引擎。

**存储之争就此裁决**：账本的事件模型不变（只追加 + 折叠 + 更正回路，引擎无关），存储是 app 层可替换引擎——单机/局域网 = 每用户一本 JSONL（users/{uid}/ 天然租户隔离）；云端起步亦可沿用每用户文件，数据库（append-only 表）在运维需要时作为引擎升级。换引擎不动真相层与折叠层（FileIO 缝的意义）。否决：数据库与日志并立的双真源（2026-08 D3.2 伤疤）。

冲击：[ADR 0001](../adr/0001-self-use-first-open-source-grade.md) "自用优先"需修订——自用仍是第一用户与验收方式，但不再是产品边界；已立 [ADR 0007](../adr/0007-multi-user-self-hostable.md)（2026-09-03）。

## D3 建设顺序与批次划分（Q3，2026-09-03 已确认）

**已定（用户澄清，推翻此前误记）：登录注册 = 必做核心需求，随首版主干实现——不是批次清单里的一项，更不是后续升级项。**

**批次划分（2026-09-03 用户"可以的"确认）**，按依赖顺序四批：

| 批次 | 内容 | 为什么这个顺序 |
|---|---|---|
| 批次 1「能聊能记」 | 服务器核心 + 登录注册 + Web 聊天页 + 今天页 + 默认助手四工具 + 模型接入（BYOK 自部署） | 最小闭环：注册→登录→聊天→记账→看见数据；登录注册（必做核心需求）落在此批 |
| 批次 2「人格与记忆」 | 多智能体（三段配置）+ 技能/MCP + 长期记忆（三层） | 陪伴支柱成立，核心差异化 |
| 批次 3「监督」 | 定时任务（离线回合/任务会话/补跑）+ 通知通道（站内+微信） | 12 个定时任务是原始需求，但依赖前两批的人格与账本 |
| 批次 4「成品化」 | 面板成品化（分类页/进步页）+ UI 设计 pass + 公网部署硬化 | 视觉/交互打磨 + 上线形态 |

**首版边界 = 批次 1–3 合起来**（陌生人拿到能完整体验"记/伴/督"）；批次 4 的 UI 打磨与公网硬化属上线前最后一轮，不算首版功能。

**首批（批次 1）工程内容详单**：
1. 服务器核心：Node 进程装 harness + 全局账本（users/{uid}/ 隔离），HTTP API + WebSocket（聊天流式）；
2. 登录注册：用户名/密码（慢哈希），注册即建用户沙盒；
3. Web 客户端工程版：登录页 + 聊天页（流式、思维链显隐）+ 今天页（今日流水/计划/打卡，极简）；
4. 内置默认助手 + 录入工具（记账/建计划/打卡/查询）——模型只能经工具写账本；
5. 模型接入：设置页配 baseURL + Key，Key 服务端加密落盘（自部署 = 存自己机器；公网 Key 政策 → Q8.2 留后）。

锁定顺序"功能设计 → UI → 开发"微调为：工程版 UI 先行（批次 1），视觉/交互设计 pass 在批次 4 面板成品化前。

## D4 智能体模型（Q4，2026-09-03 已确认）

**提议：一个智能体 = 三段配置。**
1. 人设卡：身份/语气/行为优先级/禁止事项（原 IDENTITY + SOUL 正文，自然语言）；
2. 能力绑定：内置工具逐个开关 + 已装技能 + 已连 MCP（原 TOOLS 的机制化）；
3. 记忆注入：全局用户记忆唯一一份，自动进所有智能体的 system prompt（原 USER.md）。

运行时合成 system prompt；账本全局共享，智能体差异只在人设与能力。

### 4.1 人设卡形态（2026-09-03 已确认）

**纯自由 markdown（用户选 A，否决"混合"提案）**：人设 = 一整篇随便写的 markdown 文档，同 openclaw 的 IDENTITY/SOUL 用法。机制字段不进人设卡：智能体名称从文档一级标题推导（无标题则用文件名/默认名）；模型、头像等归"能力绑定"段。人设文档随时可改——systemPrompt() 每步重取，改动下一步即生效。

### 4.2 会话与伙伴的关系（2026-09-03 已确认，含修订）

**一个会话一个伙伴（默认），但会话内可随时切换伙伴继续对话。** 语义澄清（用户 2026-09-03）：

- 会话默认绑定一个伙伴（开新会话 = 选一个伙伴）；
- **同一会话内，用户可随时切换"当前对话伙伴"**，下一条消息由新伙伴接话；历史里每条 assistant 消息归属它当时的伙伴；
- 切换 = 换 system prompt（harness 的 systemPrompt() 每步重取天然支持），历史不丢、不另开会话；UI 在会话顶部提供伙伴切换入口（头像下拉）；
- 账本凭据溯源按"消息归属的伙伴"记录，不按会话归属（一条会话可含多个伙伴的录入，来源仍可查）。

否决"一会话一伙伴且禁止切换"（原 4.2 旧结论）：用户真实用法是"把教练叫进来插一句"，禁止切换迫使每次另开会话、打断连续语境；会话内切换 + 历史归属标记同时满足"人设不串味"（每条消息归属明确）与"语境连续"。

## D5 长期记忆（Q5，2026-09-03 已确认）

支柱："跨会话、跨智能体记住用户这个人"（USER.md / MEMORY.md / HEARTBEAT.md 的后继）。已定前提：全局唯一一份、所有智能体共享（D2/D4）。

框架：记忆设计 = 三问——怎么长出来（捕获）、怎么存（形态）、怎么进 prompt（注入）。关键资产：对话本身就是日志，记忆永远可从会话日志重建（同账本凭据语义），所以捕获允许懒、不允许丢。捕获分叉已由 5.1 收束（窄工具 + 自动凝练 + 原始层复用会话日志）。

### 5.1 DeepTutor 调研纪要（2026-09-03，D:\AI\DeepTutor）

三层记忆子系统（`deeptutor/services/memory/`）：L1 原始事件（每面每天一个 JSONL，只追加，捕获失败吞掉、不破坏主流程）→ L2 分面小结 → L3 凝练文档四槽位（recent/profile/scope/preferences）。**写入三通道权限不对称**：L1 全自动；模型工具 `write_memory` 只准写 preferences 槽、仅限用户**显式表达**的偏好（提示词明令"不要猜"）、≤240 字、优先原话、一次一条；L2/L3 凝练不在对话路径自动跑，由用户在 Memory 工作台手动触发 consolidator（LLM 批处理：update/audit/dedup，对照 L1 证据分块更新，meta.json 记已见 id 做增量，违禁短语过滤，原子写）。格式：L2/L3 markdown 内嵌 entry id 锚点（HTML 注释）+ 脚注溯源（`[^1]: chat:abc`），解析/序列化纯函数幂等。读取：`read_memory` 每 turn ≤1 次，返回四份 L3 拼接，用于调整语气/举例不抄原文；另有 stamps-only 轻量召回（只读标题+时间戳、不碰正文，返回 days_ago 防模型日期算术错）。

**映射到 OpenPrism（2026-09-03 已确认，用户"可以的"）**：三层模型采纳，两处本土化——① L1 不新建：会话日志即更全的原始层（它是 stamps，我们有全文）；② 凝练触发从"纯手动工作台"改为"**自动跑（夜间/压缩后）+ 记忆页可看可改可手动重跑**"（openclaw 教训：靠自觉不行；但生活 App 不该逼用户养工作台）。模型写入收窄为显式偏好/事实工具；记忆文档采 L3 式槽位 + 溯源脚注格式。捕获分叉 a/b/c 就此收束：窄工具 + 自动凝练 + 原始层复用会话日志。

### 5.2 记忆怎么进 prompt（2026-09-03 已确认，用户选 a）

**全量自动注入**：L3 记忆文档（画像/偏好/近期）与人设卡一起，每回合自动进 system prompt，模型零动作、第一句即"记得你"。体积由凝练层负责（audit/dedup 保证有界），不靠注入端取舍；注入时剥离溯源脚注（给人查出处的锚点不喂模型）。否决 b（工具按需）：个性化对辅导产品是增强、对陪伴产品是命根，"记得你"不能取决于模型本回合想不想调工具；否决 c（混合）：省的那点 token 抵不上失忆风险。

## D6 定时任务（Q6，2026-09-03 已确认）

### 6.1 到点执行的是智能体的"离线回合"（2026-09-03 已确认，用户选 B）

**定时任务到点 = 以所属智能体身份开一次无用户在场的回合（离线回合）**：它可读账本（今日计划完成情况）、可生成个性化消息（结合历史劝你）、可经工具落账——账本来源标记 `schedule` 的语义由本决定确立（D2 预留在此兑现）。纯文本提醒（"该睡觉了"）是其退化情形（不调工具、输出预设话术），**不设独立的纯闹钟引擎**。

- 否决 A（纯闹钟）：cron 通知器，手机自带，且 schedule 来源标记与"定时任务追问后回答进打卡闭环"（D1 支柱 2）在纯闹钟下无从谈起。
- 否决 C（A/B 双引擎）：两套语义，"提醒"想升级成"结合流水劝你"就得换任务类型；B 天然覆盖 A 的用例。
- 代价：每任务到点 = 一次模型调用（频率上限、用户不在场时的 Key 归属 → Q8）。openclaw HEARTBEAT 实践即此形态。

### 6.2 任务专属持久会话（2026-09-03 已确认，用户选 B）

**一个定时任务 = 一个专属会话；每次到点 = 调度器往该会话投一条 followup 开新 Turn；用户对通知的回复也进该会话。**

- 机制零新增：离线回合 = 普通会话里的普通 Turn，触发方从用户换成调度器；followup / Session Log / 压缩 / Turn 预算全部沿用。
- 纵向记忆：同一任务第 N 次唤醒看得到前 N-1 次的痕迹（"你上周连续三天晚睡"成立）；跨任务不串味。
- 打卡闭环落点：对通知的回复 = 该会话下一条消息，智能体调打卡工具落账，无需"回复路由"新概念。
- 会话列表将出现"任务会话"条目，呈现方式归 Q10；本条只定机制事实。

### 6.3 错过触发点：补跑、不补吵（2026-09-03 已确认，用户选 C）

**恢复后发现错过：离线回合照跑**（读账本、生成消息进任务会话、可落痕——错过的那期作为事件存在），**推送不自动吵人**：何时呈现归通知通道规则（勿扰时段、安静投递——Q9）。多次错过只补最近一次，不堆积。

- 补跑时效窗口：错过不足 24 小时补跑，更久跳过、任务历史留痕（提议默认，Q9/Q10 可细化）。
- 否决 A（纯跳过）：连续天数统计会把"系统没跑"算成"用户没打卡"，机制冤枉人、折叠指标失真。
- 否决 B（一律补吵）：凌晨 0:40 弹"该睡觉了"会让用户关掉通知权限，监督支柱死于打扰。
- 本质：离线回合是数据事件（落 Session Log、可折叠），推送只是展示面——错过的只是展示时机，不是事件本身。对自部署形态（合盖错过是常态）尤其关键。

### 6.4 任务解剖与双入口（2026-09-03 已确认，用户定 B + 补充）

**任务 = 四字段：所属智能体 + 触发时刻（结构化数据）+ 任务指令（自然语言，即每次到点投进任务会话的 followup 消息）+ 启用/暂停开关。**

- **触发时刻两类**（用户补充）：单次（具体日期时间，跑完即归档）与周期循环。周期表达 = 预设枚举（每天 HH:MM / 每周几 / 每月几号 / 每年某日）+ cron 逃生门（B，用户确认）；时刻绑定用户时区。
- **双入口**（用户确认）：① 定时任务设置菜单——表单 + 时间组件自定义；② 与智能体对话——模型调"定时任务工具"解析落字段（解析失败 = isError 可见）。两端写同一工具，UI 只是另一写入方（同账本 `ui` 来源语义）。
  - **2026-09-04 增补（用户实测反馈"只能建不能撤"）**：对话入口补齐完整 CRUD——`create_task` 之外新增 `query_tasks`（含下次到点）、`update_task`（启停/标题/指令/触发）、`delete_task`。UI 面本就齐全；模型面与 UI 面对等，用户说"这个提醒不要了"模型必须能直接删。
- **定时任务面板**（用户补充）：查看当前已启用的任务（呈现细节归 Q10，此处定"面板存在且为管理入口"）。
- 否决纯自然语言存原文（到点与否依赖模型解释 = 不确定，违反"录入唯一途径是工具"同源铁律）；否决 cron-only（生活 App 普通用户写不出）。
- 首版不做：仅限时段、结束日期等可选约束——需要那天加可选字段（D2.1 只加不弃演化规则）。

### 6.5 能力边界：离线回合与聊天回合同权（2026-09-03 已确认，用户选 A）

**离线回合 = 普通聊天回合，能用该智能体绑定的一切**（读写账本、已装技能、已连 MCP 外呼）。信任模型唯一：**绑定即授权，不区分有没有人在场**。

- 留痕即安全网：离线回合做的一切都在 Session Log（工具、参数、结果），可溯源可复盘——机制透明优先于事前阉割。
- 收紧的正规位置是 Q4b（技能/MCP 安装与绑定的信任边界），全局一刀切，不给定时任务开小灶；否则重演 6.1 否决过的"双引擎两套语义"。
- 成本护栏：Turn 预算（harness 现成）限制单回合步数；任务密度/频率上限归 Q8 成本话题。

## D9 通知通道与客户端形态（Q9，2026-09-03 已确认）

### 9.1 Web 先行，通知通道可插拔（2026-09-03 已确认，用户定）

**首版客户端 = Web（唯一形态）；系统级推送（PWA/Web Push/原生 App）整体后议。** 首版通知 = 站内在线通知（页面开着可见；未读天然落在任务会话里，打开即见）。6.3 语义不变：离线回合照跑照落账，"吵不吵、何时呈现"由通道决定——站内通道的呈现 = 打开时看见。

### 9.2 通道是双向消息网关（2026-09-03 已确认，用户选 B）

**通知通道收发对称：IM 里的回复路由进对应会话——微信 = Web 之外的第二客户端（同一会话真相，两个前端）。** 打卡闭环在微信里直接闭合：学姐在微信追问"今天学习打卡了吗"，回"做完了"即落账，不必开 Web。

- 身份绑定：IM 身份（公众号 openid / 插件身份等）↔ 用户账号，绑定关系存用户沙盒。
- 落地节奏：首版 = Web + 站内通知；微信双向通道为后续接入项，桥选型专项调研（用户确认 openclaw 已有微信直连插件，可行性有参照；官方路公众号/企微与插件路都留在调研范围）。

## D4b 技能与 MCP（Q4b，2026-09-03 已确认）

### 4b.1 形态、安装与信任边界（2026-09-03 已确认，用户"可以的"）

- **形态 = 标准格式，不发明私有格式**：技能 = 标准 Agent Skill（目录 + SKILL.md，与本仓库项目级技能同格式，外部积累直接装入）；MCP = 标准 MCP 客户端（remote URL 型工具服务器，挂 harness 工具管线）。
- **安装 = 自带自装**：设置页粘贴 git URL / 上传文件，落用户沙盒（`users/{uid}/skills/`、`mcp/`）。无商店、无市场、无官方预置目录（零预设）；分享/导入导出留远期。
- **绑定**：继承 D4——技能/MCP 为用户级资源（装一次），智能体级绑定开关。
- **信任边界 = 安装时一次说清，运行时不再设卡**：技能 = 改提示词（低危），一句话提示；MCP = 外呼数据给第三方（中危），安装时告知并确认一次；此后绑定即授权（6.5），运行中无逐次审批。
- **公网形态禁本地 command 型 MCP**（服务器替用户起任意进程 = 安全灾难），仅自部署形态开——D2b"三部署同一核心"的第一处能力差异。

### 4b.2 技能进上下文：渐进式加载（2026-09-03 已确认，用户选 B，采 ZCode 同款机制）

**目录常驻 + 正文按需**（参照 ZCode skill 加载，2026-09-03 实测确认）：

- **目录层（每回合常驻 system prompt）**：绑定技能的 `name` + `description` + `when_to_use` 而已，非正文。体积硬约束对齐 ZCode：`description` 超 1024 字符 = 装不进（拒绝或截断，实现期定）；触发靠描述前 ~250 字符写清"何时用"，无关键词匹配。
- **正文层（按需载入）**：模型点名某技能 → 经工具以 name 载入 → SKILL.md 全文那一刻进上下文。载入动作 = 工具事件落 Session Log（"模型可见即日志可重建"铁律天然满足）。
- **MCP 工具不在此问内**：工具 schema 每回合随请求全量下发是机制天然，无需决策。
- 否决 A（全量注入）：技能体积无界（想装多少装多少），绑 10 个每回合白烧几万 token 必爆；记忆 5.2 全量成立是因为凝练层保证有界，技能无此收敛。

### 11.1 信息架构（IA）与命名「生活温度版」

左侧固定纵向菜单（`w-60`）+ 左下角个人头像下拉（个人设置/退出）。去技术化命名（用户 2026-09-03 定"生活温度版"）：

- **主导航**：对话 / 今天 / 盘面（原「足迹」）/ 成长
- **次导航**：伙伴 / 提醒
- **会话记录**：并入左侧纵列（在「提醒」下），按时间倒序，不再单开一栏；顶部「新对话」入口
- **头像下拉**：提醒、技能、MCP、长期记忆、模型接入、通知通道 + 主题切换 + 退出登录

十二页：登录、聊天、今天、盘面、成长、任务、伙伴、伙伴编辑、技能、记忆、模型接入、通知通道。

### 11.2 主题「深林墨绿」

CSS 变量 token，明暗两套：

- **白天「深林墨绿·成长」**：墨绿 `#2f6b4f` + 金 `#b98a3e`，暖米底 `#f6f4ee`。
- **黑夜「森林夜色」**：苔绿 `#7fb08f` + 琥珀铜 `#c99a5b`，带绿调的近黑 `#0e1410`。是白天墨绿的**去饱和延伸**，不是靛蓝——否决了初版靛蓝深夜（用户"AI 味太浓"，靛蓝/紫=LLM 默认色）。
- 图标：手写 Lucide 风格线性 SVG（`stroke-width:1.5`、`currentColor`），弃 emoji（AI 味）。

### 11.3 盘面 = 分类即维度（Q7 的 UI 落点）

盘面页顶部一排**分类 chip**（每个一个色标），点选切换；下面整块盘面（汇总卡 / 14 天趋势 / 30 天热力图 / 本月明细）随当前分类走，颜色也随分类变。三条多分类兜底：

1. **横滑**：chip 行 `overflow-x-auto`，多了向右滑不换行。
2. **「全部」聚合 chip**（排第一）：不分分类，跨分类合并总账，明细带出「哪一分类」的色标。
3. **分类管理面**（设计兜底，未入原型）：合并（健身/跑步→运动，历史不丢）+ 归档（停用保数据）。分类从流水**动态长出**，非预设目录，正常生活维度有界（十几个到头）。

### 11.4 切换伙伴（Q4.2 的 UI 落点）

一会话一伙伴（默认），但会话内可随时切换。聊天头部显式「切换伙伴」按钮 + 头像下拉，切换 = 换 system prompt（harness `systemPrompt()` 每步重取天然支持），历史不丢、不另开会话；每条助手消息归其伙伴。

### 11.5 热力图

近 30 天 = 5 列（每周一列）× 7 行（周一→周日），最近一周在最右；固定 12×12px 小方块，`grid-template-rows: repeat(7, 12px)` + `grid-auto-columns: 12px`，不随容器拉伸。
