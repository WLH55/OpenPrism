## D0 成品定义与路线图框架（Q0，2026-08-30 已确认）

**成品 = 作者日常真实使用不缺功能，且陌生人拿到后按 README 能跑通同等体验。** 与 ADR 0001 咬合：自用是验收方式，开源标准是架构底线。
- Q4–Q8 全部在路线图内，只有先后、没有范围闸门；D2 的双维度深度优先降级为构建顺序（面板模板本就六维通用）。
- 采集管线（always-record）属成品必含；连接器排最后一批（依赖事件模型稳定），首个候选 Chatlog（微信/QQ 记录）。
- dev 分支第一批交付（2026-08-31 定稿）：存储迁移（直录/更正/目标全部读写全局事件日志 + 镜像器 + rebuild 命令）→ 更正回路（`openprism_correct` + UI 删除编辑）→ `occurredAt`/`recordedAt` 时间语义 → 采集管线（捕获 → 夜间提炼）→ 面板成品化（kind 驱动 widget、周期切片、热力图、目标进度、快速录入表单、移动优先）→ 每日/每周简报（会话内先行）。微信投递（im-bridge）与 Chatlog 连接器属第二批。
- 移动端适配为成品必含约束（形态拷问见 Q9）。

## D2 MVP 维度范围（Q2，默认采纳）

**双维度闭环：理财 + 情感。** 在现有 `expense`/`mood` 代码基础上，把这两个维度的全链路（录入 → 提取 → 纠错 → 面板 → 周报）做穿做透；事件模型与面板模板保持通用，第三个维度作为"少量代码就能加"的验证点。

理由：调研显示六维全铺的维护半径是同类项目弃坑首因；闭环深度（尤其是纠错回路）比覆盖广度更决定面板可信度。

## D3 数据架构（Q3，提议中，待确认）

**提议：会话日志为唯一事实源 + 可重建的全局物化事件库。**

- `openprism/*` 事件只写 dsh 会话日志（录入凭据永远在会话里，可溯源）；
- OpenPrism 订阅 `session/event`，把所有会话中的 `openprism/*` 事件镜像到全局 append-only 日志（`data/openprism/events.jsonl`，每行带 `sessionId` + `seq`）；
- 面板 / 周报 / 模型查询工具从全局日志折叠，不再看单会话；
- 提供 rebuild 命令从 dsh 会话日志全量重建全局日志（物化层永远是可丢的缓存语义）。

### 3.1 「openprism/* 事件」的语义（2026-08-30 已确认）

**事件 = openprism_* 工具的 `tool/call` + `tool/result` 调用记录；不写自定义事件类型。**
原提议字面上与 v0.2 的会话日志白名单结论冲突（未知事件类型被拒绝加载、`ignorable` 只读、无第三方注册面——见插件 README「数据模型」节）。工具调用天然以标准事件落在会话日志，参数即完整录入凭据；镜像器订阅 `session/event`，过滤 openprism_* 调用物化为全局事件；rebuild = 扫描全部会话日志中的 openprism_* 调用重放。

### 3.2 storage-domain 四张表的命运（2026-08-30 默认采纳，可推翻）

**废弃四张表与 `storages/openprism.json`，全局事件日志成为唯一持久层；面板/工具查询从全局日志全量折叠进内存。**
理由：3.1 确认后工具直写表即成双真源（重试、手改文件必漂移）；个人量级一年几千条事件，折叠毫秒级，持久化缓存属过早优化，真慢了再加不迟；少一个双写面、少一条 storage seam 依赖，「一个 jsonl 就是全部数据」对本地优先/可导出是加分项。连带改动：工具 execute() 不再写表；插件不再注入 `storageDomain`；`panel.json` 读折叠结果；事件追加按单实例假设处理（多实例并发追加同一 jsonl 有交错风险，个人场景成立，ADR 里写明）。分类的默认播种/增删改也走全局日志（见 3.3）。

### 3.3 非会话写入与 rebuild 语义（2026-08-30 已确认）

**非会话写入直接追加全局日志，每条事件带来源 `source`：`mirror`（会话镜像）/ `ui`（面板操作）/ `internal`（工具内部副作用，如自动建类、默认播种）。**
覆盖三类不经 openprism_* 工具调用的写入：对话自动建类、面板 UI 分类增删改名、默认分类播种；日志只有一个文件、一个追加面，镜像器只负责会话来源的事件。**rebuild = 会话重放生成 `mirror` 事件 + 现有日志中 `source ≠ mirror` 的事件原样保留合并**（否则 rebuild 会抹掉 UI 建的分类）。否决：UI 操作伪装成会话走镜像（滥用 dsh 会话语义）；分类单独存表（回到双存储，违背 3.2）。

背景事实（探查 dsh 0.1.1-rc.2 得出）：dsh 的投影机制是每会话的（`ctx.sessionProjections` 按 session 折叠、cell 只活内存）；持久化由插件订阅 `session/event`/`session/flush` 负责；没有跨会话投影。

否决的备选：纯会话日志扫描（需解析 dsh 内部日志格式，预发布阶段无兼容承诺，耦合脆）；独立存储直写（破坏"录入即写会话日志"的重放语义，纠错时两个真源打架）。

## D4 事件模型与纠错（Q4）

### 4.1 更正事件（2026-08-30 已确认）

**任何纠错 = 追加一条更正事件 `{ kind: 'correction', target: <原事件id>, op: 'update' | 'delete', ... }`，折叠时最后一条更正生效；原始事件永不改写。**
两个入口都要，对话优先：对话纠错走新工具 `openprism_correct`（模型定位最近匹配的记录并追加更正）；面板最近记录列表加删除/编辑入口，端点直接追加更正事件（顺手清掉 README「没有删除/编辑入口」这条已知限制）。
否决：改写日志历史（违反仅追加，凭据溯源报废）；只做删除标记不做内容更正（「金额记错」这一最高频场景无法表达）。
实现前提：mirror 事件 id 确定性派生（如 hash(sessionId + 调用序号)），rebuild 后 id 不变、更正引用不断链——待核实 dsh tool/call 是否带稳定标识（本地未装依赖，实现前探查）。

### 4.2 事件时间语义（2026-08-30 已确认）

**事件带两个时间：`occurredAt`（发生时间，模型从对话推断，未提及则取录入时刻）+ `recordedAt`（录入时间，系统生成、永不缺失）；面板/周报的周期切片一律按 `occurredAt`，「最近记录」展示两者。**
理由：现状 `time: Date.now()` 用录入时间冒充发生时间，「补记昨天」会系统性污染以天为单位的历史切片，且错误一旦写入日志无法洗掉；两字段同时落地了调研映射里 Graphiti「字段设计预留时间语义」的承诺。
否决：单 time 字段（省事但切片污染是硬伤）；照搬 Graphiti 全套 validFrom/validTo 生命周期区间（无持续型事实前属过度设计，演进时再加）。

### 4.3 自动去重、两阶段提取、规则引擎（2026-08-30 已确认）

**以产品路线图取代 MVP 分层：三者的数据模型地基已在 3.3 + 4.1 就绪，按依赖排序实现，不设范围闸门。**
- mem0 两阶段提取的决策词汇（ADD/UPDATE/DELETE/NOOP）与 4.1 更正事件同构：ADD=普通录入、UPDATE/DELETE=更正、NOOP=不产出事件；「模型调用即决策」是直录与采集管线共用的单阶段形态，管线化（见 Q5）无需新事件类型。
- 规则引擎：3.3 的 `source` 枚举天然预留 `rule`；规则产出即追加相应来源的事件，事件模型无需扩展。
- 自动去重 = 规则引擎的一种策略（对重复模式产出 DELETE 更正），不单独立项。
- 实现顺序：直录 + 更正回路 → 采集管线与两阶段提取 → 规则引擎。

## D5 采集管线（Q5）

### 5.1 采集日志独立存储（2026-08-30 已确认）

**采集原料（captures）存独立的 append-only 采集日志，按月分片（`captures/YYYY-MM.jsonl`）；管线产出的结构化事件进全局日志并回链 `captureId`；面板折叠不碰原料。**
- 保留策略退化为「删整月文件」（如提炼完成后原文保留 N 天；借鉴 workbench 按月分片 + 隐私边界标注）；
- 与 ADR 0002 的关系：「唯一持久层」指**面板数据**；原料不是面板数据、不进折叠（→ ADR 0003）；
- 管线幂等：同一 captureId 的产出去重，崩溃重跑安全。
否决：capture 混入全局日志（原料与事实混流、折叠需过滤、裁剪 = 改写违反仅追加）；不落盘原料实时处理完即丢（放弃「先落库再处理」的可靠性初衷）。
实现前核实：dsh `session/event` 是否向插件暴露用户消息原文（采集挂点）。

### 5.2 捕获范围与意图路由（2026-08-31 已确认）

**默认全量捕获 + per-session 排除清单；意图路由在提炼层执行：非生活原料提炼时判 NOOP 丢弃，原料到期随整月裁剪。**
- 理由：漏采不可找回、多采可裁剪；本地存储成本可忽略；原料本就随对话过模型 API，采集不新增隐私暴露面（借鉴 workbench 逐路径隐私标注）。
- 双路径重复的消解：提炼的决策输入携带「该会话已直录的事件」，重复判 NOOP——与 4.3 的决策词汇同构。
- 语音/图片文本先行：微信语音/图片等 im-bridge 语音 + ASR 能力落地再进（图片先存引用不提炼）。
否决：绑定制（每开新会话要记得绑定，绑错 = 静默漏采）；只采微信会话（GUI 对话漏采）。

### 5.3 批处理节奏（2026-08-31 已确认）

**晚间批量为主 + 错过补跑：dsh jobs 定时缝挂夜间任务，批量提炼当天未处理的 captures；产出事件回链 `captureId`、`source` 增 `extraction` 值；当天未跑则下次 dsh 启动补跑（`captureId` 幂等保证重跑安全）。**
- 直录仍是实时路径，管线只兜底——夜间延迟换 token 成本可控（OpenClaw 教训：成本前置控制）；提炼跑 dsh 模型面，模型档位随宿主配置，OpenPrism 只控制批量大小与频率。
- 给 Q7 留钩子：次日简报带「昨晚提炼了 N 条」。
否决：逐条实时提炼（token 成本翻数倍，实时感已由直录覆盖）；纯手动触发（违背零操作采集）。

## D6 面板与视图（Q6）

### 6.1 目标/预算体系（2026-08-31 已确认）

**目标/预算本身也是事件：追加 `kind: 'goal'`——`{ dimension, metric, target, period: daily/weekly/monthly, note }`；修改与废止走 4.1 的更正事件，同样仅追加、可溯源、rebuild 不变。**
- 入口双轨（与分类管理同款）：对话 `openprism_set_goal` 工具 + 面板 UI 目标管理；
- 面板折叠时按 period 窗口算「当期实际 vs target」出目标进度 widget；理财典型用法是分类月预算，超支提醒接 Q7 钩子；
- metric 取值限定为可从事件折叠出的聚合（支出合计、活动时长/次数、心情打卡数等）。
否决：goals 放声明式配置文件（第二存储，违背 3.2 单真源；失去纠错能力）；不做（面板缺「对照期望」半边，产品级体验不完整）。

### 6.2 面板信息架构（2026-08-31 已确认）

**骨架「总览 + 六维度页签」不变；kind 驱动 widget（声明式落在数据形状而非自由拖拽布局）；周期切片今日/本周/本月/今年按 `occurredAt`；每维度记录密度热力图；空态模板；页签顶部快速录入表单（不经模型）；目标进度 widget 置顶；移动优先（单列、底部导航）；刷新保持 5 秒轮询（长连接列为后续评估项）。**
- 砍掉心光式高频词云：依赖 note 关键词提取、价值存疑——真需要让 Q7 周报用 LLM 现算。

## D7 主动简报（Q7，2026-08-31 已确认）

**两种简报 + 派生物不进日志 + 微信投递为主：**
- 每日简报（清晨生成）：昨日收支/心情/活动速览 + 「昨晚提炼了 N 条」反馈（5.3 钩子）+ 目标进度与超支提醒（6.1 钩子）；
- 每周周报（周日晚）：本周 vs 上周对比、趋势，加一段 LLM 现算的解读（调研「AI 朋友每周来信」的落地）；
- 生成分工：数据部分折叠 + 模板（确定性、零 token），仅解读段落过 LLM；词云类文本分析也在这层现算，不建索引；
- 产物存储：`reports/YYYY-MM/` 按月 markdown——简报是可随时重算的派生物，不进全局日志（ADR 0002 的「唯一持久层」只管面板数据）；
- 投递：微信推送为主（im-bridge；缺跨插件服务缝——fork 或等上游，实现期再定），dsh 会话内同时可见；超支/目标达成提醒搭每日简报的车，不做独立推送通道。
- 调度（2026-08-31 补确认）：三个定时任务（提炼/日报/周报）的时刻经插件 config 自定义、不写死在代码里
- 面板设置（2026-08-31 再补确认）：调度配置升级为**面板 ⚙ 设置页签**——schedule.json
  持久化 + GET/POST /openprism/schedule 端点，保存即热生效无需重启；patch config 降级为
  schedule.json 缺席时的引导值（headless 部署用）。
  （`cordis.patch.yml` 的 openprism 行 config 块；默认 03:00 / 07:00 / 周日 21:00，null 关闭，
  weeklyBriefingDay 定星期）；dsh-schedule 是模型侧会话提醒、jobs 缝是后台任务运行时，均非本需求的用户面。

## D8 连接器（Q8，2026-08-31 已确认）

**第一个连接器 = Chatlog（微信/QQ 聊天记录读取 → 灌入采集日志，走同一提炼管线）；im-bridge 微信通道不算独立连接器，并入 Q7 简报投递实现；连接器落地时事件加 `channel` 字段（对话/微信/表单，机制轴 `source` 不变）。**
- 连接器形态 = 插件内的外部数据源模块；screenpipe 式 pipe 协议/市场是远期演进，不预建。
否决：im-bridge fork 先行（录入路径先于数据源成熟，采集日志初期只剩对话自身）；直接上协议/市场（当前体量过度设计）。

## D9 移动端形态（Q9，2026-08-30 已确认）

**录入与查看两半分开解：录入走微信通道（im-bridge followup 注入绑定会话——微信即移动端），查看走响应式 Web + PWA 增强（添加到主屏），原生 App 明确排除。**
- Q6 面板重设计以「移动优先」为约束；访问组网（局域网 / Tailscale 等）不属本项目范围。
- 微信语音/图片录入依赖 im-bridge 的语音 + ASR 能力（workbench 同款 P2 项），随通道能力演进；采集管线先做文本。
否决：PWA 当主形态、在手机浏览器跑长对话（体验差且 dsh 会话 UI 的移动适配不受我们控制）；原生/混合 App（与「一切皆 dsh 插件」相悖，工作量差量级）。

### 增补：dsh-workbench 规划借鉴（2026-08-30，源自 2026-08-16 dsh-workbench SDD Spec）

定位差异一句话：workbench 是「自由指标打卡台」（八大维度 + 任意指标），OpenPrism 是「策展维度的生活面板」——不合并定位，只借机制。

| 借鉴点 | workbench 的做法 | OpenPrism 怎么用 |
|---|---|---|
| 简报投递通道 | dsh-im-bridge 已有 iLink 微信双向通道（扫码登录 + 长轮询 + followup 注入绑定会话） | Q7 周报/提醒投递的现成通道；Q8 采集入口多一个「微信直说」渠道。缺口：无跨插件服务缝、推送文案固定、仅文本——fork（workbench P2 同款）或等上游 |
| 定时器 | dsh 有 jobs 服务端定时缝（GUI 看板 cron 只是 P0 权宜） | Q7 定时周报/晚间简报的挂点，无需自研调度 |
| dsh 挂载点清单 | 源码验证七项：tools / jobs / turn-end / followup / approval / 插件形态 / skill | 实现期对照：Q5 采集挂 session/event，Q7 挂 jobs + turn-end，录入表单挂 webServer |
| 采集原料按月分文件 | data/2026-08.jsonl 按月分片、追加不修改 | Q5-1 采集日志按月分片 → 保留策略（如提炼后 30 天删原文）退化为「删整月文件」 |
| 多入口与 source 双轴 | source: wechat/gui/form 是「渠道」轴 | OpenPrism 的 source 是「机制」轴（mirror/ui/internal/rule），两轴正交：机制照旧；渠道（channel）字段等连接器落地再加 |
| 表单直录不经模型 | P1 表单页直录，隐私边界明确标注「不经模型」 | Q6 面板 UI 补快速录入表单：零 token、精准，兼作隐私敏感场景的入口 |
| 目标/预算体系 | goals 声明式（metric+target+period）且回执带 goalProgress；Firefly 亦有预算 | OpenPrism 缺目标概念——列为 Q6 新增拷问点：预算/目标作为可更正的声明式事件，面板出目标进度 widget |
| metric kind 词汇 | kind: duration/count/amount/checkin/rating/note | 不引入自由指标（维度是策展的），但把 kind 作为 Q6 声明式面板的 widget 选择依据（amount→合计+趋势、rating→均值、duration→热力） |
| git 版本化数据 | data 目录 git init，JSONL 人类可读可回滚 | 可选能力：事件日志所在目录 git 化 = 免费备份，与 rebuild 互补 |
| 演进式交付 | P0 skill 零代码先行 → P1 插件 → P2 fork 桥 | 新功能先用 skill/模型现算验证价值再上管线（如周报先在会话内生成，后接 jobs + 推送） |
| 隐私边界逐路径标注 | 「NL 汇报经模型 API；表单直录不经模型」 | Q5 采集管线照做：原料本就随对话过模型 API，采集不新增暴露面，但保留策略因此更有价值 |
