# 0004 移动端独立 App，推翻 dsh 插件路线

OpenPrism 从 dsh 组合包重写为**安卓原生 App**（Expo React Native + TypeScript），本库插件代码全部删除、git 历史与 docs 保留。驱动是作者的真实使用形态：每天在手机上随手记录与查看，而插件形态要求桌面常开 dsh 宿主（Node 进程 + 会话日志 + web UI），与该形态根本冲突；dsh 全量约 21.8 万行 Node 代码也无法运行于安卓。领域模型（仅追加事件日志、更正链、双时间戳、折叠——ADR 0002/0003）作为**规格**在新代码中重新实现，不移植任何旧代码；旧 `events.jsonl` 可选导入。引擎不复刻 dsh 代码、复刻其设计模式：自写 OpenAI 兼容客户端（流式 + 工具调用 + provider 中立错误识别）与极简 agent 循环；存储为 App 私有目录的 JSONL 文件（事件 / 会话 / 简报，格式照搬），密钥入 SecureStore。镜像器与 rebuild 机制随宿主消失而蒸发——App 自有会话，工具执行直接落事件日志。

## Considered Options

- **继续插件路线（v0.4 现状，六批次 68 测试绿）**：功能最全且已在日常使用，但绑定桌面宿主，手机使用无从谈起。
- **Node 服务端 + 手机客户端**：引擎可复用，但要养一台常开机器，违背自用简单性；组网负担同 2026-08 D9 的排除理由。
- **Capacitor / WebView 壳**：后台与离线能力最弱，且 D9 已否决壳形态。
- **Kotlin + Compose 或 Flutter 原生**：脱离现有 TS/React 技能栈，交付最慢，与「最近就要用」冲突。

## Consequences

- 放弃 dsh 白得的能力（审批、沙箱、压缩、Web UI、插件生态），引擎与 UI 全部自持，自写量估算数千行。
- 事件日志格式不变：旧数据一行命令导入；导出 / 备份 = 分享文件的数据主权保持。
- 安卓后台受限（doze / OEM 杀后台）：定时任务以补跑为主、精确闹钟尽力而为，可靠性承诺相应弱化（→ 设计纪要 2026-09 M4）。
- ADR 0001「自用优先、按开源标准架构」的精神不变；被推翻的是交付形态（dsh 组合包），非产品定位与领域模型。
